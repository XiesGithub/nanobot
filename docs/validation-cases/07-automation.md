# 07 Cron、Heartbeat 与通知（8 项）

共用规则见 [索引](README.md)。业务时间固定为2026-10-01 09:00 Asia/Shanghai；所有投递只进入测试 outbox。业务等待与实际处理延迟分离。

## V053 一次提醒建立与触发

- **前置**：Cron 无任务，当前测试用户目标 test/client-01。
- **用户输入**：“今天09:30提醒我交报告，只提醒一次。”
- **需要验证的输出**：恰好一条一次计划，目标时刻2026-10-01T01:30:00Z；09:29无通知，推进至09:30后恰好一次“交报告”提醒；之后再tick不重复。
- **如何验证**：模式R+D，F 检查 schedule/target，O 比较前后 outbox；T 记录创建与触发回调。不要求回复的任务ID固定，不真实等待30分钟。

## V054 每日计划及时区

- **前置**：无计划，timezone=Asia/Shanghai。
- **用户输入**：“每天北京时间09:00提醒我检查备份。”
- **需要验证的输出**：重复计划为该时区每日09:00；下一次触发为2026-10-02T01:00:00Z，之后为10月3日同刻；不能按UTC09:00触发。
- **如何验证**：F 校验 cron 表达式的语义、tz和 next_run；D 用固定业务时钟推进两个日期，O每天一条。创建时09:00已经到达，下一次按服务已确认的未来调度规则计算，不临场变更gold。

## V055 列出并删除指定计划

- **前置**：两条既存任务固定逻辑ID j1/j2，消息分别“交报告”“检查备份”，都在未来触发；ID通过列出结果可取得。
- **用户输入**：“列出提醒，删除‘交报告’那条，保留‘检查备份’。”
- **需要验证的输出**：j1删除、j2保持原计划；推进到两条原计划时刻后仅j2投递。
- **如何验证**：T 确认先取得真实ID再 remove，F检查任务集合与j2字段不变，O检查唯一保留通知；只说删除但任务还在失败。

## V056 不合法时区拒绝创建

- **前置**：无计划。
- **用户输入**：“每天09:00按时区Mars/Olympus提醒我交报告；不要替我改用别的时区。”
- **需要验证的输出**：明确时区无效/需要有效时区；无任务新增，不能默默回退UTC。
- **如何验证**：S 核对错误及无虚假成功；F任务集合为空；D 强制给工具非法tz验证真正校验。不是可恢复故障场景。

## V057 正常重启后计划保留

- **前置**：通过真实Cron建立09:30一次提醒并完成持久化；09:10正常停止服务、新进程加载同一实例。
- **用户输入**：“保留09:30交报告的提醒，重启后仍要生效。”
- **需要验证的输出**：重启前后逻辑计划只有一条、时刻和目标不变；09:30正常投递一次。
- **如何验证**：D控制服务生命周期，F核对存储与加载，O检查计数；不在此题声称“外发成功后任意崩溃都恰好一次”，该保证需要明确幂等契约。

## V058 Heartbeat 无变化不通知

- **前置**：HEARTBEAT.md 指令“读取health.txt，仅异常时通知”；health.txt为“状态正常，没有新变化”；模型决策调用可观察。
- **用户输入/触发**：“按配置检查一次状态，仅有异常才通知我”；触发一次Heartbeat tick。
- **需要验证的输出**：决策为skip或run后通知门抑制；outbox为零；不会把内部决策/配置路径当通知发给用户。
- **如何验证**：R检查决策及通知；D分别固定合法skip与run+无变化结果覆盖两条路径，T/O核对；读取/处理成本仍记录，静默不代表零成本。

## V059 明确提醒与错误必须通知

- **前置**：两个独立事件：一次提醒到点结果“提醒：交报告”；后台任务结果“备份失败：磁盘不可用，需要检查”。
- **用户输入/触发**：“到点提醒我交报告；备份检查失败也要告诉我”；依次注入两个固定任务结果。
- **需要验证的输出**：两项都通过通知门，outbox各一条，目标正确；不因消息短/重复任务文字而抑制明确提醒。
- **如何验证**：R用真实evaluate_response判定，D固定通知工具的should_notify=true检验交付链；O核对事件与投递，S检查没有泄漏内部理由。错误本身是通知输入，不算一次业务故障恢复成功。

## V060 通知评分失败时不丢重要结果

- **前置**：后台固定结果“备份失败：磁盘不可用”；通知判断的Provider调用抛受控连接异常，业务任务本身已结束。
- **用户输入/触发**：“备份失败时通知我”；将结果提交现有通知判断入口。
- **需要验证的输出**：evaluate_response降级为notify=true，重要结果正常交付一次；不输出异常中的隐藏细节或凭据。
- **如何验证**：模式D，T验证异常确实发生、fallback布尔值为真；O核对一次投递，S检查用户仅看到固定业务错误。这是明确的通知降级契约，费用未知需标注。
