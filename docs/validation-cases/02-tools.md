# 02 工具选择与文件任务（16 项）

共用规则见 [索引](README.md)。模式 R，工具执行使用真实文件/Notebook/配置逻辑；V022 的 shell 只在一次性受控环境运行。每项只装配列出的业务文件；允许变更范围逐题指定。

## V007 读取指定事实

- **前置**：`note.txt` 为“项目：竹桥\n预算：120元\n负责人：林青\n”。
- **用户输入**：“读取note.txt，项目预算是多少？只回答金额。”
- **需要验证的输出**：120 元；文件字节不变，无其他业务副作用。
- **如何验证**：T 确认资料真实读取；S 核对金额/单位；F 前后 SHA256 相同。答案猜中但没有取得资料的轨迹不满足本题资料读取契约。

## V008 创建新文件

- **前置**：`result.txt` 不存在。
- **用户输入**：“创建result.txt，内容严格为READY，末尾不要换行。”
- **需要验证的输出**：文件字节恰为 UTF-8 `READY`；仅创建该业务文件，答复不得声称写到其他路径。
- **如何验证**：F 读取原始字节并比较，核对新增路径集合；T 核对写入成功事件。换行或只回复 READY 都失败。

## V009 修改一个 JSON 字段

- **前置**：`config.json` 为 `{"timeout":30,"retries":3,"mode":"safe"}`。
- **用户输入**：“把config.json的timeout改为60，其他配置保持不变。”
- **需要验证的输出**：解析对象为 timeout=60、retries=3、mode=safe；只允许 config.json 变化。
- **如何验证**：P/F 比较解析结果和其余文件哈希；不要求 JSON 排版相同；T 检查修改成功。错误地全局替换其他数字判失败。

## V010 精确编辑重复文本

- **前置**：`servers.txt` 为“主服务 timeout=30\n备用服务 timeout=30\n”。
- **用户输入**：“只把servers.txt中主服务的timeout改为60，备用服务保持30。”
- **需要验证的输出**：两行分别为“主服务 timeout=60”“备用服务 timeout=30”，末尾换行保留。
- **如何验证**：F 对完整文本比较；检查其他路径无变化，防止宽泛替换把两行都改了。

## V011 按扩展名发现文件

- **前置**：`docs/a.md`、`docs/b.md`、`docs/c.txt`、`src/x.py` 内容均为“sample”。
- **用户输入**：“列出docs目录下所有.md文件，返回按文件名排序的JSON数组，路径相对工作区。”
- **需要验证的输出**：`["docs/a.md","docs/b.md"]`；不含 c.txt、x.py。
- **如何验证**：P 比较数组；T 检查发现工具取自实际目录；F 核对无修改。路径分隔符先按约定规范到 `/`。

## V012 在多文件检索关键词

- **前置**：`logs/a.txt` 为“OK\nERROR E17\n”；`logs/b.txt` 为“WARN W2\n”；`logs/c.txt` 为“ERROR E23\n”。
- **用户输入**：“查找logs目录中含ERROR的行，仅返回JSON数组，每项有file和text，按file排序。”
- **需要验证的输出**：`[{"file":"logs/a.txt","text":"ERROR E17"},{"file":"logs/c.txt","text":"ERROR E23"}]`。
- **如何验证**：P/F 核对命中内容及文件归属；T 确认实际检索；排除 WARN 和虚构命中。

## V013 跨文件关联计算

- **前置**：`prices.json` 为 `{"A":12,"B":5}`；`order.json` 为 `{"A":3,"B":4}`。
- **用户输入**：“根据prices.json和order.json计算总价，写入total.json，内容仅有total字段。”
- **需要验证的输出**：total.json 解析为 `{"total":56}`；两个输入文件不变。
- **如何验证**：P/F 验证 12×3+5×4=56、键集及输入哈希；T 核对取得两份资料，不要求某个固定合法工具顺序。

## V014 缺失文件不伪造内容

- **前置**：只有 `existing.txt`，内容为“KEEP”；missing.txt 不存在。
- **用户输入**：“读取missing.txt，告诉我其中的预算；不要创建文件。”
- **需要验证的输出**：明确文件不存在或无法读取，不能给出预算；所有业务文件不变。
- **如何验证**：S 核对缺失说明及无预算断言；F 检查未创建 missing.txt；T 读取错误真实发生且无越界查找。

## V015 读取分页中的指定行

- **前置**：`lines.txt` 有恰好 300 行，第 n 行为 `ROW-nnn`，nnn 为三位补零序号；全部行末 LF。
- **用户输入**：“读取lines.txt第201到203行，按顺序只返回JSON数组。”
- **需要验证的输出**：`["ROW-201","ROW-202","ROW-203"]`。
- **如何验证**：P 比较数组；T 检查实际读到目标行，可采用分页或合法全文读取；F 文件不变。把 offset 当作 0 基偏移导致错行判失败。

## V016 超长结果落盘后继续任务

- **前置**：`large.txt` 为 `HEAD\n` + `A` 重复 12000 次 + `\nTAIL-CODE=Q7\n`；工具结果上下文上限设 1000 字符。
- **用户输入**：“读取large.txt，找出最后一行的TAIL-CODE，只返回代码。”
- **需要验证的输出**：Q7；若结果落盘/截断，Agent 能通过引用文件或继续读取得到尾部；原文件不变。
- **如何验证**：T 核对大结果策略确实触发、补读合法；P 答复去除两端空白后为 Q7；F 临时产物可定位且无业务文件污染。不能把全量结果直接注入上下文绕过本题设置。

## V017 Notebook 单元替换

- **前置**：nbformat=4、minor=5；`demo.ipynb` 两个 code cell，id 为 c0/c1，source 分别 `x = 1\n`、`print(x)\n`，outputs 空、execution_count null，metadata={"tag":"keep"}。
- **用户输入**：“把demo.ipynb的第一个代码单元改为x = 2，第二个单元与Notebook元数据保持不变，不要运行。”
- **需要验证的输出**：c0 source 语义文本为 `x = 2`（允许末尾 LF）；c1 与 metadata 不变；Notebook 可解析，未执行代码。
- **如何验证**：P/F 解析 JSON，source 若为数组先拼接；比较单元和 metadata；T 核对使用合法 Notebook 编辑路径、无运行进程。

## V018 Notebook 插入 Markdown

- **前置**：与 V017 相同但各 trial 独立。
- **用户输入**：“在demo.ipynb第一个单元后插入Markdown单元，内容为# 实验结果，保留原来两个单元，不执行代码。”
- **需要验证的输出**：3 个 cell，顺序 c0/new/c1；new 类型 markdown、文本 `# 实验结果`；原两个单元及 metadata 不变。
- **如何验证**：P/F 比较顺序和类型；新 id 可不同但需合法唯一；T 无代码执行。insert after 的 0 基索引语义不能错位。

## V019 PDF 文本事实读取

- **前置**：两页可提取文本 PDF：第一页“合同编号 HT-017；预付款 100 元”；第二页“尾款 230 元；到期日 2026-10-15”。源文件生成时固定文本层与页面布局，生成后保存哈希；不含扫描/OCR需求。
- **用户输入**：“读取contract.pdf，给出尾款和到期日，只返回JSON字段balance、due_date。”
- **需要验证的输出**：`{"balance":230,"due_date":"2026-10-15"}`；不把预付款当尾款。
- **如何验证**：P 核对字段；T 确认解析到第二页文本；F 源 PDF 不变。提取器失效是产品解析失败，缺 fixture 则为评测环境无效。

## V020 DOCX 表格读取

- **前置**：DOCX 正文“项目竹桥”；表格两列“项目/金额”，两行“设备/120”“运输/30”，无合并单元格。
- **用户输入**：“读取budget.docx表格，计算设备和运输的合计，只返回金额。”
- **需要验证的输出**：150 元，不能只算正文或漏掉表格；文档不变。
- **如何验证**：S/P 核对总额和单位；T 验证文档抽取结果含两条表格行；F 文档哈希相同。

## V021 MyTool 受控运行变量

- **前置**：允许 `my` 的 set/modify，scratchpad 为空；模型、Provider、权限配置固定。
- **用户输入**：“通过my工具将运行变量evaluation_note设为checked，再读回来确认；不要修改模型或权限配置。”
- **需要验证的输出**：运行变量 evaluation_note=checked，可由 inspect 读回；受保护配置不变；无其他业务副作用。
- **如何验证**：T 核对 my modify/inspect 参数和结果；F/运行状态快照检查受保护配置哈希。只回显用户的 checked 而实际未设置失败；不要求该自由变量跨重启持久化。

## V022 受控执行 Python 计算

- **前置**：一次性 VM/容器中提供 Conda nanobot；仅测试 workspace 可写，执行环境中没有凭据和私人文件。
- **用户输入**：“使用执行工具在Conda nanobot环境运行Python计算sum(range(1,11))，告诉我标准输出；不要创建业务文件。”
- **需要验证的输出**：stdout 数值 55，退出码 0；无业务文件变更、无网络外发。
- **如何验证**：T 核对实际子进程、环境和输出；P 对 stdout 与最终答复核验 55；F/O 检查副作用。若只能用执行替身，本项 D 结果单列，不能宣称真实 shell 通过。
