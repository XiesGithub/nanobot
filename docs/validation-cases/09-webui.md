# 09 WebUI（8 项）

共用规则见 [索引](README.md)。模式B，真实浏览器和测试网关；固定事件流用于UI契约，真实模型profile用于完整任务，两者分开报告。操作以按钮角色/可访问名称定位，不用易变CSS class；桌面默认1280×800。

## V073 发送消息到最终完成

- **前置**：空会话；固定事件模式assistant依次输出delta“5”、完成事件；真实profile正常运行固定模型。
- **用户输入/操作**：输入“2加3是多少？只回答数字。”并点击发送。
- **需要验证的输出**：用户气泡一条、assistant最终正文5，生成状态退出；输入框可发送下一条，无重复气泡或控制台错误。
- **如何验证**：U检查DOM文本/气泡计数与按钮状态；T关联一次业务提交和完成事件；从点击/接受到最终DOM可见分别计时。mock最终正文不能冒充真实能力结果。

## V074 工具进度和实际文件结果

- **前置**：config.json=`{"timeout":30,"retries":3}`；真实工具可用，固定事件模式也执行真实编辑后推送对应进度。
- **用户输入/操作**：“把config.json的timeout改为60，retries保持3。”
- **需要验证的输出**：工具进度可见且终态正确；最终回复与文件一致，JSON为timeout60/retries3；没有把工具事件当最终文本重复显示。
- **如何验证**：U核对工具开始/结束及最终气泡；F读文件；T确认进度关联真实工具事件，而非只有UI模拟“成功”。浏览器最终成功但文件失败则整题失败。

## V075 ask_user 选项与恢复

- **前置**：固定控制脚本先发ask_user“报告用表格还是JSON？”，选项“表格”“JSON”；恢复后执行真实写入report.txt，内容 `{"total":150}`。
- **用户输入/操作**：“把设备120、运输30整理为报告，先问格式”；选“JSON”。
- **需要验证的输出**：等待期间显示两个可选择项、未写文件；选JSON的输入只提交一次，恢复后文件正确并退出等待，不重复弹同题。
- **如何验证**：U检查选项可用与点击效果，T检查ask/resume ID和请求计数，F前后文件；键盘操作与点击作为环境变体，重复可靠性按同profile统计。

## V076 停止后允许新的继续请求

- **前置**：首任务已读取fact.txt=“值73”，第二个工具停在可取消gate，尚未写result.txt；停止时持久化检查点可观察。
- **用户输入/操作**：“读取fact.txt，再写result.txt为73”；看到gate进度后点击停止；停止完成后输入“继续完成刚才的任务”。
- **需要验证的输出**：停止后、继续前无新的写入；界面能发送后续请求；继续后result.txt为73，最终状态清楚，无重复气泡/工具结果。
- **如何验证**：B固定控制事件保证停止点；T检验真实取消与恢复消息配对，F检验时间分段的文件状态，U核对按钮和结果。只验证已确认文件写契约，不对任意非幂等工具声称恢复恰好一次。

## V077 会话切换期间结果正确归属

- **前置**：会话A任务阻塞在gate，固定最终“A=17”；会话B空，固定最终“B=23”。
- **用户输入/操作**：A发送“返回A=17”；切到B发送“返回B=23”；让A晚于B完成，再切回A。
- **需要验证的输出**：B界面只有B对应结果，A结果落入A历史；切回后A可见A=17，未把A内容插入B。
- **如何验证**：U分别检查两会话DOM和历史，T核对chat_id、订阅和请求顺序；DOM只显示当前会话，不能只比全局消息数组。

## V078 刷新后加载已有历史

- **前置**：完成一次用户“返回HISTORY17”/assistant“HISTORY17”，已成功保存。
- **用户输入/操作**：浏览器刷新，再打开原会话。
- **需要验证的输出**：原用户/assistant各一条；不重新执行任务、不额外模型调用；原会话ID不变，媒体/文本加载逻辑不报错。
- **如何验证**：U对刷新前后有效气泡计数和正文，T检查history请求与模型调用账本；刷新本身不能算成新的任务成功。

## V079 邮件引用可展开核对

- **前置**：测试owner已认证，授权邮件M1正文“竹桥预算120元”，查询结果引用对应M1；另一主体无权限。
- **用户输入/操作**：“竹桥预算是多少？给出邮件依据”；点击引用卡片。
- **需要验证的输出**：答案120元，引用展开显示对应原文和来源；加载权限凭证/会话绑定正确，不显示别的邮件；失去owner权限后再次读取被拒绝。
- **如何验证**：U核对答案与卡片，P/S比较来源文本，T检查引用请求身份；失权变体校验403或现有拒绝契约及DOM无私有正文。不把仅显示引用标题视为原文验证成功。

## V080 移动视口与主题下关键交互

- **前置**：viewport=390×844，分别浅色/深色；文本字体/浏览器版本固定，空会话。
- **用户输入/操作**：打开会话列表、新建会话、关闭列表，在输入框发送“返回MOBILE17”；再打开列表切换回来。
- **需要验证的输出**：控件可见可操作、无被遮挡的发送入口；正文MOBILE17可读，页面无意外横向溢出；焦点进入/退出侧栏符合组件可访问性约定。
- **如何验证**：U用bounding box、scrollWidth/clientWidth、可访问角色和焦点断言，保存两主题关键截图与DOM/几何证据，由程序自动检查；需要视觉语义但固定模型能力未验证的条款标为未判定，按阶段1协议复判，不要求人工抽查；除非固定渲染环境，不把每个像素相等当唯一门槛。实际模型或固定事件分别报告。
