# 05 子 Agent（6 项）

共用规则见 [索引](README.md)。异步任务必须通过 spawn/真实 SubagentManager；spawn 接纳回执不是完成。任务 ID 可动态生成，断言关联关系而非固定 UUID。

## V041 委派并返回事实

- **前置**：nums.json 为 `[2,4,6]`，主/子 Agent 可读；最大并发子任务1。
- **用户输入**：“请委派子Agent读取nums.json求和，子任务完成后告诉我结果。”
- **需要验证的输出**：子任务完成，结果12回到原会话，最终可见答复正确；只建立一个必要子任务，无其他文件/外发。
- **如何验证**：T 确认 spawn、子 runner、完成 announce、主任务汇总因果链；P/S 核对12；子任务结束后才标 completed，合计主/子调用成本。

## V042 两个子任务结果汇总

- **前置**：a.json=`[1,2,3]`，b.json=`[10,20]`；允许并发2。
- **用户输入**：“分别委派两个子Agent求a.json和b.json的和，等两个都完成后，按JSON字段a、b、total汇总。”
- **需要验证的输出**：`{"a":6,"b":30,"total":36}`；两个子任务各完成一次；结果没有互换。
- **如何验证**：P 比较对象；T 以任务/数据源映射验证归属，使用 gate 固定 b 先于 a 完成的 D 变体；不能靠完成顺序当索引。

## V043 子任务失败真实告知

- **前置**：bad.txt 读取总是由受控工具返回不可恢复“document unavailable”；没有备用数据。
- **用户输入**：“委派子Agent读取bad.txt中的预算，完成后告诉我。”
- **需要验证的输出**：清楚说明子任务没取得预算，不虚构金额或称成功；子任务终止、资源释放、错误回到原会话。
- **如何验证**：S 检查失败说明；T 检查子任务 error/终止和关联，F/O 无副作用。这是永久失败正确处理，不进入可恢复故障分母。

## V044 /stop 取消当前会话子任务

- **前置**：子任务工具 slow_read 在 started gate 阻塞，可取消；其他会话另有一个不会受本会话停止影响的子任务。
- **用户输入**：“委派子Agent读取slow.txt”；收到 started 信号后“/stop”。
- **需要验证的输出**：目标会话子任务取消，停止后无新工具/成功完成回执；其他会话任务正常结束；停止结果清楚。
- **如何验证**：模式 D 控制必触发，R 可补真实交互；T 按 session_key 检查取消对象、取消传播和停止后事件；O 核对无迟到成功消息。已发生副作用不要求凭空回滚。

## V045 并发上限阻止超额启动

- **前置**：maxConcurrentSubagents=1，第一个子任务停在 started gate，无法立即完成。
- **用户输入**：“同时委派两个子Agent，分别处理a.txt与b.txt。”
- **需要验证的输出**：同一时刻运行子任务数不超过1；第二次 spawn 被拒绝或等第一个结束后合法启动；最终状态说明与实际接纳一致。
- **如何验证**：D 固定两个 spawn 请求保证边界被测；T 验证事件区间最大重叠数、接纳/拒绝结果；若第一任务结束后重试，检查仅新启动一次。拒绝不能包装成“两个都已启动”。

## V046 子任务回注归属与历史持久化

- **前置**：会话A任务结果固定“A-result=17”，会话B固定“B-result=23”；按 B→A 顺序投递真实 subagent announce，两个任务 origin 不同。
- **用户输入**：A：“我的子任务结果是多少？”；B：“我的子任务结果是多少？”
- **需要验证的输出**：A=17、B=23；各自结果在对应历史保存一次，重启后不会丢失或再保存一份；回复目的地正确。
- **如何验证**：模式 D+R；T 检查 task_id/origin/session mapping，F 比较正常完成→重启后历史的有效结果数，O 目标匹配。此题不额外要求平台没有定义的跨任意重复事件去重。
