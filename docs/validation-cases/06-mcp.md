# 06 MCP（6 项）

共用规则见 [索引](README.md)。测试服务固定名称 eval；工具 `lookup_order(order_id:string)` 的 schema 和响应由 fixture 冻结。配置支持的 stdio/SSE/streamableHttp 按环境变体报告，网络替身与真实本地服务器区别标明。

## V047 发现并调用 MCP 工具

- **前置**：服务器暴露 lookup_order；对 A17 返回 `{"order_id":"A17","status":"shipped","tracking":"T900"}`，其他编号返回 not_found。
- **用户输入**：“使用已连接的订单服务查询A17，只返回JSON字段status、tracking。”
- **需要验证的输出**：`{"status":"shipped","tracking":"T900"}`；工具发现注册成功、实际查询A17，无虚构状态。
- **如何验证**：T 核对 discovery、注册名及服务器调用账本，P 比较对象；服务器只有该订单，不能通过公开知识替代。

## V048 非法参数拒绝后修正

- **前置**：lookup_order schema order_id 必须字符串；固定模型回放第一次给数组 `["A17"]`，得到参数错误后第二次给字符串“A17”。
- **用户输入**：“查询A17的发货状态。”
- **需要验证的输出**：非法请求未进入服务器执行；修正请求执行一次，最终 shipped；参数错误可被模型看到，未崩溃。
- **如何验证**：模式 D；T/P 检查 prepare/validate 的错误和服务器账本只接收字符串；核对模型下一请求包含错误结果。R 自发合法调用不算覆盖非法参数分支。

## V049 MCP resource 与 prompt

- **前置**：服务有 resource `fixture://eval/policy`，文本“退货期限14天”；prompt `policy_answer` 文本“根据提供的政策作答，不补充未给条款”；通过项目已有 wrapper 暴露。
- **用户输入**：“读取订单服务的政策资源，采用policy_answer提示模板，告诉我退货期限。”
- **需要验证的输出**：14 天；resource 和 prompt 都通过服务真实读取，没有补写收费/例外规则。
- **如何验证**：T 核对资源/提示 wrapper 被发现与调用；S 核对期限和无新增条款；若服务只暴露工具，环境预检无效，不能当本题通过。

## V050 三种传输保持相同业务结果

- **前置**：同一个 eval 服务分别以 stdio、SSE、streamableHttp 暴露 V047 数据，三个配置分开运行。
- **用户输入**：“查询A17的tracking，只回答编号。”
- **需要验证的输出**：每个适用配置均为T900；初始化、调用、清理完成；退出后无残留连接/子进程。
- **如何验证**：P/T 比较各变体业务值，逐项验证协议握手和清理；分别测耗时。某传输缺依赖显示未验证，不能从其他传输外推通过。

## V051 MCP 超时后恢复

- **前置**：tool_timeout=2秒；第一次 lookup_order 在请求接纳 gate 后等待5秒，后续请求立即返回V047数据；调用预算允许一次合法重试。
- **用户输入**：“查询A17，如果服务短暂超时，恢复后再尝试一次。”
- **需要验证的输出**：第一次超时有可见工具错误；第二次取得shipped/T900；未因 cancel-scope 异常取消整个业务请求；无残留挂起任务。
- **如何验证**：D 固定调用序列，R 补实际规划；T 确认故障实际发生和第二请求成功，P/S核对答案。独立统计超时恢复率；5秒模拟等待不能依靠真实网络碰巧触发。

## V052 Windows stdio 启动路径

- **前置**：Windows 测试实例中 MCP 启动器路径含空格，例如测试目录“mcp service”；launcher 为批处理包装，实际 Python 服务使用 Conda nanobot；无凭据。
- **用户输入**：“通过本地MCP订单服务查询A17的tracking。”
- **需要验证的输出**：T900；launcher 路径/参数完整传入，stdout 只有 MCP 协议，错误日志在 stderr；退出能清理服务。
- **如何验证**：模式 D 或 R；T 核对进程参数和握手，P 检查结果；stdout 污染或空格拆参失败明确记录。Linux 不适用，单列而非算成功。
