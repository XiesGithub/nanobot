分步数据流

→ → → →

POST /v1/chat/completions

aiohttp 路由把请求交给 handle_chat_completions(request)。AgentLoop 已经存放在 request.app 中，不会每次请求重新创建。

JSON 或 multipart

JSON 走 request.json() 和 _parse_json_content()；上传文件走 _parse_multipart()。两条路径最终都归一成 text 与 media_paths。

模型名称校验

请求中的 model 必须等于当前服务暴露的模型名。API 兼容 OpenAI 格式，但不允许请求任意切换服务端 Provider。

api:{session_id}

相同的 session_id 会映射到同一个会话历史；没有提供时使用默认 API Session。

同 Session 串行

处理函数先进入该 Session 的 asyncio.Lock，再在超时限制内调用 agent_loop.process_direct(...)。

流式与非流式

非流式

等待整个 Agent 完成，取得 OutboundMessage.content，再一次性返回 Chat Completion JSON。

流式

on_stream 将 token 写入异步队列，HTTP 协程持续写 SSE；只有整个 Agent 完成才关闭流。

易错点：一次 LLM 流结束不等于一次 Agent 请求结束。模型可能暂停输出去调用工具，然后继续下一段模型输出，因此 SSE 不能在第一次 on_stream_end 时关闭。

你应该能回答

  • 为什么 AgentLoop 放在 request.app，而不是每个请求重新创建？
    查看答案收起答案

    AgentLoop 持有 Provider、工具注册表、SessionManager、MCP 连接和会话运行状态，创建成本高且必须跨请求共享。create_app() 将同一个实例放进 request.app，处理函数只取用它。

  • 为什么 process_direct() 外面还需要 Session lock？
    查看答案收起答案

    HTTP 的 process_direct() 路径绕过了 AgentLoop._dispatch() 的会话串行机制。API 层因此用按 session_key 保存的 asyncio.Lock，防止同一历史被两个请求同时读取和写回。

  • JSON 和 multipart 两条输入路径最终统一成了什么？
    查看答案收起答案

    两条路径都归一成用户文本 text 和本地附件路径列表 media_paths，随后连同生成的 session_key 传给 process_direct()。
