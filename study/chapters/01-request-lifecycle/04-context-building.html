身份与工作区约束

identity.md 描述运行平台、工作区和核心行为；工作区中的 AGENTS.md、SOUL.md、USER.md、TOOLS.md 作为 bootstrap 文件载入。

长期与近期记忆

MemoryStore 提供已整理的长期记忆；尚未被 Dream 处理的最近历史以有上限的 Recent History 形式加入。

当前 Session 历史

Session.get_history() 同时受最大消息数和 replay token budget 限制，避免把整个历史无限发送给模型。

运行元数据

当前时间、channel、chat ID、sender ID 被放入明确标记的 metadata block，声明“这是元数据而不是指令”，降低注入风险。

当前用户内容

纯文本保持字符串；图片读取为 base64 image_url block，并保留原始路径元数据供持久化时替换。

为什么要合并连续同角色消息

某些模型 API 要求 user/assistant 角色严格交替。如果历史最后一条已经是 user，而当前输入又追加一条 user，ContextBuilder 会合并两者内容，而不是制造两个连续 user message。多模态场景会先把字符串转换成统一 block 列表再合并。

上下文预算的三道保护

Messages
Session 回放限制最大消息数量
Tokens
为模型输出预留空间后计算回放预算
Chars
Recent History 和工具结果有字符上限
持久化与模型输入不是同一个列表：Runner 可以为模型临时修复、裁剪或压缩上下文，但不能让这些合成修改改变“本轮新增消息从哪里开始”的保存边界。

你应该能回答

  • system prompt、Session history 和 Recent History 有什么区别？
    查看答案收起答案

    system prompt 是每轮重建的可信规则与能力说明；Session history 是已持久化的对话记录；Recent History 是长期记忆尚未消费的历史片段，由 ContextBuilder 作为补充上下文注入，三者来源和生命周期不同。

  • 为什么运行元数据要明确标注“不是指令”？
    查看答案收起答案

    channel、chat_id、sender 等运行元数据来自外部请求，可能含有攻击性文本。代码把它放入 user-side 的 runtime block，并明确声明不是指令，避免提升到 system 权限。

  • 为什么先保存用户消息，再调用可能失败或被取消的模型？
    查看答案收起答案

    BUILD 在调用 Runner 前把当前 user message 写入 Session。这样模型异常、长时间重试或用户 /stop 时，请求仍可恢复，checkpoint 也有稳定的用户起点。
