空结果有明确兜底

如果 Runner 返回 None 或空白文本，SAVE 状态替换为 EMPTY_FINAL_RESPONSE_MESSAGE，避免产生不可解释的空回复。

只保存本轮新增消息

save_skip = 1 + len(history) + early_user 跳过 system prompt、已存在历史和已经提前保存的用户消息。

移除瞬态数据

base64 图片替换为路径占位符；runtime metadata block 可被移除；过长工具文本按策略截断，然后通过 SessionManager 原子写入。

构造渠道无关响应

_assemble_outbound() 处理 ask_user 按钮、生成媒体、流式标记和 MessageTool 抑制，得到统一 OutboundMessage。

由调用者决定交付协议

API 转成 Chat Completion JSON/SSE；MessageBus 路径发布到 outbound queue；Python SDK 转成 RunResult。

为什么不能直接保存 Runner 的整个 messages？其中包含每轮动态 system prompt、重复历史、base64 图片和运行元数据。全部保存会造成指数式重复、文件膨胀和上下文污染。

OutboundMessage 是统一返回契约

字段含义交付层用途
channel响应目标类型选择 API、WebSocket 或聊天平台
chat_id目标会话将消息发回正确聊天
content最终可见文本JSON content 或消息正文
media生成或附带媒体图片、文件等输出
buttons交互选项ask_user 的快捷选择
metadata流式、线程等控制信息入口/Channel 的协议适配

三种返回路径

HTTP API

response.content → _chat_completion_response() → web.json_response()；流式路径则持续写 SSE chunk。

MessageBus

_dispatch() 调用 bus.publish_outbound(response)，ChannelManager 消费后发送到对应平台。

Python SDK

Nanobot.run() 提取 content，并通过 SDKCaptureHook 收集 tools_used 和 messages，返回 RunResult。

MessageTool 特例

如果工具已经主动发送了用户可见消息，最终自动回复可能被抑制，避免用户收到重复内容。

你应该能回答

  • save_skip 为什么必须考虑提前保存的用户消息？
    查看答案收起答案

    当前 user message 可能已在 BUILD 阶段提前写入 Session。若 save_skip 只跳过 system 和旧 history，SAVE 会把它再次追加，因此公式还要加上 user_persisted_early 对应的一条。

  • 为什么 base64 图片不能原样长期保存到 history.jsonl？
    查看答案收起答案

    Base64 会让每轮 replay 和 JSONL 文件迅速膨胀，还会反复占用模型 token。持久化前代码把图片块替换成带原始路径的文本占位，当前轮需要的图片仍保留在临时模型消息中。

  • Agent 返回 OutboundMessage 后，为什么仍需要入口层再适配一次？
    查看答案收起答案

    OutboundMessage 只表达渠道无关的内容、媒体、按钮和 metadata。HTTP 入口还要编码为 JSON/SSE，MessageBus 路径要发布到目标 Channel，SDK 则要转换成 RunResult。
