Normalization boundary

外部输入怎样转换成 Agent 消息

所有入口都要把自己的协议细节收敛成 InboundMessage。内部核心由此不需要理解 HTTP、Telegram 或 WebSocket。

输入：Python 参数或 Channel 事件统一类型：InboundMessage

两条进入核心的路径

直接调用路径

HTTP API / Python SDK → process_direct() → InboundMessage → _process_message()

不经过 MessageBus，调用方直接等待返回值。

渠道事件路径

Channel → MessageBus.inbound → AgentLoop.run() → _dispatch() → _process_message()

适合长期运行的 Gateway 和多个聊天平台。

共同汇合点：两条路径最终都调用 AgentLoop._process_message(msg)，后续 Agent 逻辑完全一致。

InboundMessage 的字段

字段含义核心层如何使用
channel来源，例如 api、cli、telegram提示词运行上下文和最终响应路由
sender_id发送者身份审批身份、工具上下文、日志
chat_id聊天或房间标识默认 Session key 和响应目标
content用户文本构造成当前 user message
media本地媒体路径列表文档提取或图片编码
metadata入口特有的附加信息流式标记、线程、message_id 等
session_key_override覆盖默认会话键线程会话、统一会话等特殊路由
nanobot/bus/events.py核心结构
@dataclass
class InboundMessage:
    channel: str
    sender_id: str
    chat_id: str
    content: str
    timestamp: datetime
    media: list[str]
    metadata: dict[str, Any]
    session_key_override: str | None

    @property
    def session_key(self) -> str:
        return self.session_key_override or f"{self.channel}:{self.chat_id}"

nanobot/agent/loop.py:1669直接入口
async def process_direct(self, content, session_key, channel, chat_id, media, ...):
    await self._connect_mcp()
    msg = InboundMessage(
        channel=channel,
        sender_id="user",
        chat_id=chat_id,
        content=content,
        media=media or [],
    )
    return await self._process_message(
        msg, session_key=session_key, ...
    )

你应该能回答

  • 为什么核心只依赖 InboundMessage，而不直接依赖 HTTP Request？
    查看答案收起答案

    InboundMessage 是渠道无关的数据契约；HTTP、Telegram 或 WebSocket 只在边界层做协议解析。核心因此只处理 channel/chat_id/content/media/metadata，无需导入任何传输层类型。

  • process_direct() 与 AgentLoop.run() 的入口路径有什么不同？
    查看答案收起答案

    process_direct() 由 API/SDK 直接构造 InboundMessage 并等待 _process_message()；run() 则长期消费 MessageBus，经 _dispatch() 建立并发与投递任务后进入同一核心函数。

  • session_key_override 为什么有必要？
    查看答案收起答案

    默认键是 channel:chat_id，但线程会话、统一会话、API 自定义会话和后台结果可能需要把历史归到另一个键。覆盖字段让“消息投递目标”和“历史归属”可以分离。
