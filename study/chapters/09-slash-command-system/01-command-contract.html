@dataclass
class CommandContext:
    msg: InboundMessage
    session: Session | None
    key: str
    raw: str
    args: str = ""
    loop: Any = None

六个字段分别解决什么问题

→→→→

msg 保留传输身份

Handler 从中取得 channel、chat_id 和 metadata，因此响应能返回原会话；/restart 也用它跨进程保存通知目标。

session 允许为空，key 不为空

Turn 状态机内调用时 Session 已加载；外层快速分流时传入 None，Handler 需要时再通过 loop.sessions.get_or_create(key) 获取。

raw 与 args 分离

raw 保留用户输入；prefix 匹配后 Router 按前缀长度切出 args，并保留参数原始大小写供 Handler 自行解释。

loop 是命令的能力入口

命令直接访问 sessions、consolidator、dream、bus、tasks 与 provider。它功能强但耦合高，因此 MyTool 明确禁止检查或修改 commands。

返回值已经是渠道响应

Handler 返回 OutboundMessage | None，不再经过 ContextBuilder、Provider 或 AgentRunner；None 表示未处理或无响应。

展示契约与执行契约是两张表

BuiltinCommandSpec

保存 command、title、description、icon、arg_hint。它服务于 WebUI palette、帮助文本与用户发现，不含 Handler。

CommandRouter

保存 command/prefix 到 Handler 的映射。它决定命令是否真的可执行，却不知道标题、图标或参数提示。

一个 Handler 的标准形态

command/builtin.py:452–459/help
async def cmd_help(ctx: CommandContext) -> OutboundMessage:
    return OutboundMessage(
        channel=ctx.msg.channel,
        chat_id=ctx.msg.chat_id,
        content=build_help_text(),
        metadata={**dict(ctx.msg.metadata or {}), "render_as": "text"},
    )

Handler 负责把原消息的寻址信息带回去，也负责决定渲染提示。错误通常被转换成用户可读内容，而不是进入 LLM 的 tool-error 恢复路径。

一致性风险：元数据与 Router 分开维护，渠道还可能维护第三份菜单。新增命令若只改其中一处，就会出现“菜单里有但不能执行”或“能执行但用户发现不了”。Telegram 当前的 /history 就值得在最后一页重点审查。

  • 为什么外层快速分流时 session 必须允许为 None？
    查看答案收起答案

    priority 命令在外层 run 循环、Session lock 和 Session 加载之前执行，以便立即停止或查询；因此构造 CommandContext 时可能还没有 Session，Handler 必须能按需加载。

  • args 为什么不直接存进 InboundMessage？
    查看答案收起答案

    args 是 Router 匹配 prefix 后从原始命令临时切出的执行参数，不是所有入站消息的通用协议字段。放入 CommandContext 可保持 InboundMessage 渠道无关且不可被入口伪造解析结果。

  • 展示元数据和执行注册分离会带来什么维护风险？
    查看答案收起答案

    UI palette/help 可能展示已删除或尚未注册的命令，Router 也可能新增命令却不被渠道发现。当前 Telegram /history 漂移就是例子，因此 metadata、Router 和渠道表必须联动测试。
