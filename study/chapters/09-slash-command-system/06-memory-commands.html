/dream、/dream-log、/dream-restore：Memory 的运维界面

Memory 系统通过三个命令暴露“执行整理—审阅变更—安全恢复”的闭环。命令层没有重新实现 Dream，而是把 AgentLoop 已持有的 Dream、MemoryStore 与 GitStore 组合成用户可操作界面。

从整理到恢复的闭环

→→→→

先返回 “Dreaming...”

Handler 创建后台 task 后马上返回 OutboundMessage，避免长时间的两阶段 LLM 整理阻塞命令响应。

后台任务再发送最终结果

dream.run() 返回是否做了工作；Handler 计算耗时，把 completed/nothing/failed 结果直接发布到 outbound bus。

日志读取 Git 中的权威版本

无参数查看最新 commit diff；带 sha 调用 show_commit_diff。未初始化、无版本、sha 不存在都有独立提示。

无 sha 时先列候选版本

/dream-restore 默认列出最近 10 个 commit，并提示先用 dream-log 预览，避免盲目恢复。

恢复本身仍可审计

git.revert(sha) 不抹掉历史，而是生成新的安全 commit；响应列出受影响文件和新 sha，之后仍能再次审阅。

/dream 是“两次响应”命令

command/builtin.py:195–221接受确认 + 完成通知
async def _run_dream():
    try:
        did_work = await loop.dream.run()
        content = "Dream completed ..." if did_work else "Dream: nothing to process."
    except Exception as e:
        content = f"Dream failed ...: {e}"
    await loop.bus.publish_outbound(OutboundMessage(..., content=content))

asyncio.create_task(_run_dream())
return OutboundMessage(..., content="Dreaming...")

这里的后台 task 使用裸 asyncio.create_task，不像 /new 的归档那样进入 loop._background_tasks 管理。阅读 shutdown 语义时应注意这个生命周期差异。

日志模式的两个分支

/dream-log

取 git.log(max_entries=1)，再显示最新 commit 的 diff；输出包含 commit、时间、变更文件和对应 restore 指令。

/dream-log <sha>

直接 show_commit_diff(sha)；若找不到，提示用裸 restore 列版本或裸 log 看最新，而不是抛 Git 异常给用户。

恢复不是 reset

恢复语义：用户指定的是“撤销这个 Dream change”，不是“把整个工作区硬重置到某一提交”。使用 revert 生成反向变更和新 commit，保留了操作轨迹，也让恢复动作本身可以被 /dream-log 审计。

错误与边界矩阵

情况行为为什么
Dream 无待处理消息完成通知为 nothing to process不是错误
Dream.run 抛异常捕获并发送耗时与错误文本后台异常必须对用户可见
Git 未初始化且 cursor=0提示先运行 /dream区分“从未运行”与版本设施异常
sha 不存在返回引导文本避免直接暴露底层 Git 错误
revert 成功返回新 sha 和文件清单构成可审计闭环

  • /dream 为什么需要两条 OutboundMessage？
    查看答案收起答案

    Dream 可能耗时，Handler 先返回“Dreaming...”让当前命令立即结束，再由后台 task 执行并通过 MessageBus 发布完成/无工作/失败结果；因此用户能看到接收确认和最终结论。

  • /dream-restore 不带 sha 时为什么只列版本？
    查看答案收起答案

    恢复是有副作用的版本操作。无 sha 时先列最近提交并提示用 /dream-log 预览，让用户明确选择目标，避免默认回滚错误版本。

  • revert 相比 reset 提供了什么安全属性？
    查看答案收起答案

    git revert 创建反向变更的新安全提交，原 Dream 提交和恢复动作都保留在历史中；reset 会移动历史指针并隐藏审计链，也更难同步与再次撤销。
