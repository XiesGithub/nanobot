Agent 聊天斜杠命令：绕过 LLM 的控制平面

当用户发送 /status、/stop 或 /dream-log 时，nanobot 不需要模型理解意图。它把同一条 InboundMessage 交给一个确定性的 Router，执行后直接产生 OutboundMessage。

核心心智模型：斜杠命令是 Agent 的“控制平面”，负责取消、重启、会话管理、状态查询与 Memory 运维；普通消息进入“推理平面”，才构建 Context、调用 LLM 并执行 Tool。两者共享 MessageBus 和 OutboundMessage，却拥有不同的决策路径。

以 /status 为例：完整数据流

→→→→

渠道只负责保留命令文本

WebSocket 把输入原样变成消息；Telegram 会先移除 @botname，再把下划线别名规范化为 nanobot 的连字符命令。

仍然使用统一消息总线

命令不是独立 HTTP RPC。它和普通对话一样进入 MessageBus.inbound，因此复用 channel、chat_id、metadata 和 session key。

/status 可走 priority 快速路径

run() 在创建普通处理任务前检查优先命令，直接调用 Handler；它无需等待同一会话正在运行的模型任务。

Handler 直接读运行时对象

cmd_status 通过 CommandContext.loop 读取模型、usage、会话、Context 估算与活动任务，不产生模型请求。

响应回到原渠道

Handler 返回带原 channel/chat_id 的 OutboundMessage，AgentLoop 发布到 outbound bus，由 ChannelManager 路由给用户。

内置命令一览

命令路由级别主要副作用
/stoppriority取消当前会话的 Agent tasks 与 subagents
/restartpriority记录通知目标，随后用 os.execv 替换进程
/statuspriority + exact只读运行状态；空闲和忙碌场景都可达
/newexact取消任务、清空 Session、后台归档未整理消息
/history [n]exact + prefix读取并裁剪当前会话历史
/dreamexact后台启动 Dream，立即返回接受确认
/dream-log [sha]exact + prefix读取 Dream Git 版本及 diff
/dream-restore [sha]exact + prefix列出或 revert 一个记忆版本
/helpexact从命令元数据生成帮助文本
