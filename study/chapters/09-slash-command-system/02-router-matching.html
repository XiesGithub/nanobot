CommandRouter：四级匹配与参数提取

Router 是纯内存路由表，不依赖 Provider、SessionManager 或 Channel。它把“需要抢占”的命令与普通命令分开，并用最长前缀优先避免参数型命令互相遮蔽。

def prefix(self, pfx, handler):
    self._prefix.append((pfx, handler))
    self._prefix.sort(key=lambda p: len(p[0]), reverse=True)

匹配顺序

→→→→

priority 不在普通 dispatch 内

AgentLoop.run() 先调用 is_priority，匹配后使用 dispatch_priority。这样它不必等待 session lock。

exact 做完整字符串匹配

/new 可匹配，/new now 不匹配。字典查找简单确定，不会把额外文本误当参数。

prefix 提取尾部参数

/history 5 命中 "/history "，然后执行 ctx.args = ctx.raw[len(pfx):]；参数的原始大小写不被破坏。

interceptor 是动态兜底接口

每个 interceptor 可检查上下文并返回响应，None 表示继续。当前默认命令没有注册 interceptor，它是 Router 已预留但尚未使用的能力。

None 意味着交还 Agent

Router 不会因为文本以 / 开头就报“未知命令”。未匹配时 Turn 转入 BUILD，所以 /foo 会成为普通用户消息。

为什么每个带参数命令通常注册两次

command/builtin.py:480–486空参数 + 有参数
router.exact("/history", cmd_history)
router.prefix("/history ", cmd_history)

router.exact("/dream-log", cmd_dream_log)
router.prefix("/dream-log ", cmd_dream_log)

router.exact("/dream-restore", cmd_dream_restore)
router.prefix("/dream-restore ", cmd_dream_restore)

若只注册 prefix，裸命令没有尾随空格便不会命中；若只注册 exact，则无法携带 count 或 sha。二者指向同一个 Handler，由 Handler 判断 args 是否为空。

is_dispatchable_command() 的真实用途

它不是完整识别器

只检查 exact 与 prefix，明确不检查 priority 或 interceptor。因此 /stop 返回 false 并不是不可执行，而是应该走另一条更早的路径。

它是“忙碌期是否直派”的保证

当会话已有 pending queue，返回 true 表示随后调用 dispatch() 一定能命中，命令无需被塞进模型的 follow-up 注入队列。

大小写与空白语义

输入识别结果原因
/NEW 在 AgentLoop 中命中 /newrun() 先做 strip，Router 再 lower
/history 05args 为 05Router 只切字符串，数字解释属于 Handler
/DREAM-LOG AbCd命中，args 保留 AbCd匹配使用 lower 后副本，切片使用 raw
/historyx不命中注册前缀含尾随空格，避免错误吞掉相似名称
/unknown交给 Agent没有通用 slash 拒绝规则
设计取舍：Router 不做通用参数 Schema，也不抛未知命令错误。代码极小、响应确定，但每个 Handler 必须自己解析与校验 args；如果命令数量大幅增长，执行表与展示表分离会成为主要维护成本。

  • 为什么 prefix 列表要按长度降序？
    查看答案收起答案

    两个前缀可能包含关系，例如更具体的 /cmd sub 与 /cmd 。长度降序保证先命中最具体规则，否则宽前缀会抢走请求并产生错误 args。

  • 为什么 /stop 不属于 is_dispatchable_command？
    查看答案收起答案

    /stop 注册在 priority tier，而该方法按契约只检查 exact 和 prefix。这样 run 循环能把 priority 放到 session lock 之前处理，不与普通可直派命令混淆。

  • 未知 slash 文本最终会走到哪里？
    查看答案收起答案

    Router 的 exact/prefix/interceptor 都不处理时返回 None；空闲时消息继续作为普通 user Turn 进入 BUILD/Runner，所以未知 slash 可由模型理解，忙碌时则进入 pending queue 作为追问注入。
