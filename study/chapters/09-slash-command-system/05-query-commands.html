/status 聚合多个子系统

版本、模型、最近 usage、Context window、Session 消息数、uptime、主任务和 subagent 数都从 AgentLoop 读取。

估算和外部用量都允许失败

Context token 估算失败时回退到最近 prompt_tokens；Web search usage 被 suppress(Exception) 包裹，不能拖垮状态响应。

/history 只展示对话角色

读取完整 Session 后只保留 user/assistant；tool/system 被跳过，内容块只提取 text，每条最多 200 字符。

/help 不复制命令清单

build_help_text() 遍历 BUILTIN_COMMAND_SPECS，把 arg_hint 与 description 组合为统一帮助。

render_as: text 控制渠道渲染

状态、历史和帮助不希望 Markdown renderer 折叠换行或误解释内容，因此在 metadata 中明确要求文本呈现。

为什么 /status 同时注册两次

command/builtin.py:475–480priority + exact
router.priority("/stop", cmd_stop)
router.priority("/restart", cmd_restart)
router.priority("/status", cmd_status)

router.exact("/new", cmd_new)
router.exact("/status", cmd_status)

外层 run() 总会先匹配 priority，因此网关运行时通常走快速路径；exact 注册让普通 dispatch() 仍具备完整语义，便于状态机直调、测试和其他调用入口。它是一种“同一 Handler、两种时机”的注册。

  • /status 为什么要把 search usage 当成 best effort？
    查看答案收起答案

    搜索配额来自可选外部 Provider，可能网络慢、缺 key 或报错；它不是 Agent 健康状态的必要部分。Handler 用 suppress(Exception) 包裹，失败仍立即返回模型、上下文和任务状态。

  • /history 为什么不能代替模型的 Session replay？
    查看答案收起答案

    它只展示最近 1–50 条 user/assistant 文本，每条还截到 200 字并跳过 tool/system；模型 replay 会考虑 consolidated offset、摘要、工具协议、token budget 和多模态占位，两者用途不同。

  • 同一个 /status Handler 为什么属于两个 tier？
    查看答案收起答案

    priority 注册让忙碌 Session 无需等锁即可查看状态；exact 注册保证空闲 Turn 内的统一 COMMAND 状态也能匹配，并满足 is_dispatchable_command() 对非 priority 直派的契约。
