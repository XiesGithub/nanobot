Memory · heavyweight consolidation

Dream：两阶段整理长期记忆

Consolidator 只提取线索；Dream 才负责把新线索与已有长期文件进行比较、去重、纠错和增量编辑。它把“理解”与“执行修改”拆成两个模型阶段。

完整运行流程

→→→→

按 Dream cursor 增量读取

读取 cursor > .dream_cursor 的合法条目，每次只取前 max_batch_size 条；没有新条目直接返回 False。

只给 MEMORY 标注行龄

借助 Git blame 计算每行距最后修改的天数；超过 14 天加 ← Nd。行数不一致、Git 不可用或开关关闭时原样使用。

Phase 1：分析但不改文件

普通 Provider 调用、无 tools。输入包括本批 history、当前日期、MEMORY/SOUL/USER 预览；输出 [FILE]、[FILE-REMOVE]、[SKILL] 或 [SKIP]。

Phase 2：最小权限增量编辑

把分析结果交给 AgentRunner，只注册 read_file、edit_file 和仅能写入 workspace/skills 的 write_file。

完成才推进 cursor

只有 Runner 的 stop_reason == completed 才将 cursor 推进到本批最后一条；否则保留原值，下个周期重试。最后压缩 history 上限并按需 Git commit。

为什么要拆成两阶段

Phase 1 · 形成编辑计划

同时看“新发生了什么”和“旧 Memory 是否重复或过期”。分析阶段没有工具，因此不能边看边随意写盘。

Phase 2 · 执行可观察动作

Runner 产生 tool events，Dream 从成功事件构建 changelog。提示词要求精确 old_text、同文件批量修改、手术式编辑，禁止整文件重写。

三类长期文件的规范归属

文件放什么Dream 的处理原则
USER.md用户身份、长期偏好、稳定事实用户更正优先；不因“很久没修改”自动删除
SOUL.mdAgent 行为、语气与沟通方式只在行为偏好得到确认或纠正时更新
memory/MEMORY.md项目知识、决定、持续有效的工作上下文去除与 USER/SOUL 重复的副本，清理客观过期内容
skills/<name>/SKILL.md重复出现两次以上、有明确步骤的可复用流程先读 skill-creator 格式并检查现有 Skill 去重

输入上限与工具边界

Prompt 预览上限
MEMORY 32,000 字符；SOUL 与 USER 各 16,000；每条 history 预览 4,000。仅预览截断，Phase 2 仍可通过 read_file 查看完整文件。
Runner 安全预算
max_iterations 限制工具循环次数，max_tool_result_chars 限制工具结果体积，工具错误不会立即让整个任务抛异常。
写入边界
edit_file 可在 workspace 内增量改文件；write_file 的 allowed_dir 只指向 workspace/skills，防止新建任意文件。

Cursor 是 Dream 的提交点

memory.py:1060 · 概念摘录at-least-once 重试语义
if result and result.stop_reason == "completed":
    new_cursor = batch[-1]["cursor"]
    store.set_last_dream_cursor(new_cursor)
else:
    # 不推进：下次周期仍读取同一批 history
    logger.warning("cursor NOT advanced")

这个顺序避免“文件没改完但归档被标为已消费”的静默丢失。代价是：如果外部文件修改成功、但 Runner 最终没有 completed，下一轮可能再次分析同一批；因此 Phase 1 的去重与 Phase 2 的精确编辑也承担幂等保护。

自测

  • 行龄超过 14 天是否会自动删除这条 Memory？
    查看答案收起答案

    不会。14 天行龄是整理 prompt 中帮助模型判断陈旧性的信号；是否删除或合并由 Dream Agent 通过受限文件工具修改 MEMORY.md，代码没有按日期直接删除长期记忆。

  • 为什么 Phase 2 使用 AgentRunner，而 Phase 1 只做普通 chat？
    查看答案收起答案

    Phase 1 只需让模型从 raw history 生成候选摘要，普通 chat 足够；Phase 2 要读取并编辑记忆文件、遵循工具结果继续迭代，所以复用带受限 ToolRegistry 的 AgentRunner。

  • Dream 工具已经改了文件，但 Runner 未 completed，会产生什么重试语义？
    查看答案收起答案

    文件副作用可能已经发生，但 cursor 不推进；下一次 Dream 会重放同一批候选，因此工具操作必须尽量幂等，GitStore 版本也为重复或错误修改提供审计与恢复点。
