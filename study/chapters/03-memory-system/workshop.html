源码精讲与设计实作

让会话、归档和长期记忆各守一条边界

Memory 不是把全部聊天塞进 MEMORY.md。Session 保留对话事实，Consolidator 把旧轮次压成可追踪历史，Dream 再把历史整理成长效知识。可靠性的关键是“先保存证据，后推进游标”，以及理解文件原子替换与追加写的差别。

当前源码连续摘录离线阅读手工演算 + 设计实作

阅读顺序：输入输出契约 → 模块数据流图 → 核心源码精讲 → 手工演算 → 动手设计与验收。本页所有原文均按当前本地文件行号提取；演算中的固定输出由假 Provider 提供，不需要模型账户。

先确定数据与责任的交接

交接点 / 输入输出与状态约束、失败和所有者
Session.messages + last_consolidated本会话可回放的未归档后缀last_consolidated 是列表下标，随 Session 裁剪需要重置；它不是全局 history cursor。
Consolidator.archive(messages)摘要写 history.jsonl；返回 summary 或 None空输入不处理；LLM 失败退到有上限的 raw_archive。返回 None 不必然表示没有归档文件写入。
MemoryStore.append_history(text){cursor,timestamp,content} JSONL 行；返回 cursor游标递增；文本先截断再 strip_think。清理为空时仍保留空记录，不能把原泄露文本恢复。
Dream：cursor 大于 last_dream_cursor 的历史批次Phase 1 分析；Phase 2 受限文件工具编辑只有 result.stop_reason==completed 推进 Dream cursor；部分工具成功但整体失败仍会重试批次。
AutoCompact：空闲会话与 TTL归档前缀 + 保留合法最近后缀 + _last_summary跳过活动会话；普通 TTL=0 不到期；摘要同时有热缓存和 Session metadata 冷恢复来源。

1. MemoryStore.append_history

每条历史有独立游标与时间，供 Dream 增量消费。摘要也可能过长或带模板泄露，因此入口有防护。

当前源码原文 · nanobot/agent/memory.py · MemoryStore.append_history · 第 235–275 行（连续摘录）

    def append_history(self, entry: str, *, max_chars: int | None = None) -> int:
        """Append *entry* to history.jsonl and return its auto-incrementing cursor.

        Entries are passed through `strip_think` to drop template-level leaks
        (e.g. unclosed `<think` prefixes, `<channel|>` markers) before being
        persisted. If the cleaned content is empty but the raw entry wasn't,
        the record is persisted with an empty string rather than falling back
        to the raw leak — otherwise `strip_think`'s guarantees would be
        undone by history replay / consolidation downstream.

        A defensive cap (*max_chars*, default ``_HISTORY_ENTRY_HARD_CAP``) is
        applied as a final safety net: individual callers should cap their own
        content more tightly; this default only exists to catch unintentional
        large writes (e.g. an LLM echoing its input back as a "summary").
        """
        limit = max_chars if max_chars is not None else _HISTORY_ENTRY_HARD_CAP
        cursor = self._next_cursor()
        ts = datetime.now().strftime("%Y-%m-%d %H:%M")
        raw = entry.rstrip()
        if len(raw) > limit:
            if not self._oversize_logged:
                self._oversize_logged = True
                logger.warning(
                    "history entry exceeds {} chars ({}); truncating. "
                    "Usually means a caller forgot its own cap; "
                    "further occurrences suppressed.",
                    limit, len(raw),
                )
            raw = truncate_text(raw, limit)
        content = strip_think(raw)
        if raw and not content:
            logger.debug(
                "history entry {} stripped to empty (likely template leak); "
                "persisting empty content to avoid re-polluting context",
                cursor,
            )
        record = {"cursor": cursor, "timestamp": ts, "content": content}
        with open(self.history_file, "a", encoding="utf-8") as f:
            f.write(json.dumps(record, ensure_ascii=False) + "\n")
        self._cursor_file.write_text(str(cursor), encoding="utf-8")
        return cursor
  1. limit 来自调用方或硬上限；先申请下一个 cursor，再对 entry 去尾部空白并做长度保护。首次过长会告警，后续重复告警抑制。
  2. strip_think 在落盘前清理模型内部标记；raw 非空而清理为空时持久化空 content。回退 raw 会重新污染下一轮模型上下文。
  3. JSONL 以追加模式写一行，再写游标文件并返回 cursor。注意这里没有 fsync 或原子替换；不能把后面的整体重写保证套用到每次 append 上。

2. MemoryStore._write_entries / Dream cursor

当 compact_history 要丢弃旧记录时，不能把正式文件先清空再慢慢写。此段把新版本准备完整后再替换。

当前源码原文 · nanobot/agent/memory.py · MemoryStore._write_entries / Dream cursor · 第 367–401 行（连续摘录）

    def _write_entries(self, entries: list[dict[str, Any]]) -> None:
        """Overwrite history.jsonl with the given entries (atomic write)."""
        tmp_path = self.history_file.with_suffix(self.history_file.suffix + ".tmp")
        try:
            with open(tmp_path, "w", encoding="utf-8") as f:
                for entry in entries:
                    f.write(json.dumps(entry, ensure_ascii=False) + "\n")
                f.flush()
                os.fsync(f.fileno())
            os.replace(tmp_path, self.history_file)

            # fsync the directory so the rename is durable.
            # On Windows, opening a directory with O_RDONLY raises
            # PermissionError — skip the dir sync there (NTFS
            # journals metadata synchronously).
            with suppress(PermissionError):
                fd = os.open(str(self.history_file.parent), os.O_RDONLY)
                try:
                    os.fsync(fd)
                finally:
                    os.close(fd)
        except BaseException:
            tmp_path.unlink(missing_ok=True)
            raise

    # -- dream cursor --------------------------------------------------------

    def get_last_dream_cursor(self) -> int:
        if self._dream_cursor_file.exists():
            with suppress(ValueError, OSError):
                return int(self._dream_cursor_file.read_text(encoding="utf-8").strip())
        return 0

    def set_last_dream_cursor(self, cursor: int) -> None:
        self._dream_cursor_file.write_text(str(cursor), encoding="utf-8")
  1. 临时文件与正式文件位于同目录，逐条序列化写入；flush 把 Python 缓冲交给 OS，fsync 请求同步文件数据。
  2. os.replace 提交新文件；然后同步父目录以保存重命名元数据。Windows 打开目录可能 PermissionError，这里专门抑制。
  3. BaseException 分支清理临时文件并再次抛出，取消或其他异常不会被假装成写入成功。发生在 replace 之后的异常仍可能已提交新文件。
  4. Dream cursor 是另一个文本文件，读取失败或非法整数退到 0；set_last_dream_cursor 是普通 write_text。多个文件的写入不是自动组成一个事务。

3. Consolidator.pick_consolidation_boundary

选择边界要按用户轮次，因为工具调用及其结果不能被摘要窗口切成不相干的两半。

当前源码原文 · nanobot/agent/memory.py · Consolidator.pick_consolidation_boundary · 第 491–511 行（连续摘录）

    def pick_consolidation_boundary(
        self,
        session: Session,
        tokens_to_remove: int,
    ) -> tuple[int, int] | None:
        """Pick a user-turn boundary that removes enough old prompt tokens."""
        start = session.last_consolidated
        if start >= len(session.messages) or tokens_to_remove <= 0:
            return None

        removed_tokens = 0
        last_boundary: tuple[int, int] | None = None
        for idx in range(start, len(session.messages)):
            message = session.messages[idx]
            if idx > start and message.get("role") == "user":
                last_boundary = (idx, removed_tokens)
                if removed_tokens >= tokens_to_remove:
                    return last_boundary
            removed_tokens += estimate_message_tokens(message)

        return last_boundary
  1. 从 last_consolidated 起统计；没有未归档消息或无需移除 token 时返回 None。
  2. 遇到下一个 user 才能形成候选边界 (idx,removed_tokens)。先检查已累积量，再把当前 user 的 token 加进去，所以切片不包含该 user。
  3. 一旦候选前缀足够大就返回；若总量不够，返回最后合法候选，保留最后用户轮。这是合法性优先的边界选择，不是固定每 N 条截断。

4. Consolidator.archive

把可丢弃的长对话变成带上限的历史记录；模型不可用时也要尽量保住事实。

当前源码原文 · nanobot/agent/memory.py · Consolidator.archive · 第 634–667 行（连续摘录）

    async def archive(self, messages: list[dict]) -> str | None:
        """Summarize messages via LLM and append to history.jsonl.

        Returns the summary text on success, None if nothing to archive.
        """
        if not messages:
            return None
        try:
            formatted = MemoryStore._format_messages(messages)
            formatted = self._truncate_to_token_budget(formatted)
            response = await self.provider.chat_with_retry(
                model=self.model,
                messages=[
                    {
                        "role": "system",
                        "content": render_template(
                            "agent/consolidator_archive.md",
                            strip=True,
                        ),
                    },
                    {"role": "user", "content": formatted},
                ],
                tools=None,
                tool_choice=None,
            )
            if response.finish_reason == "error":
                raise RuntimeError(f"LLM returned error: {response.content}")
            summary = response.content or "[no summary]"
            self.store.append_history(summary, max_chars=_ARCHIVE_SUMMARY_MAX_CHARS)
            return summary
        except Exception:
            logger.warning("Consolidation LLM call failed, raw-dumping to history")
            self.store.raw_archive(messages)
            return None
  1. 空列表立刻 None；非空先格式化并按归档输入预算截断，然后以 system+user 两条消息调用 chat_with_retry，不提供工具。
  2. finish_reason=error 被显式转为异常；正常响应无文本时使用 [no summary]。摘要落到 append_history，并使用更紧的摘要字符上限。
  3. 任何本段 Exception 进入 raw_archive 兜底，返回 None。上层不能依据 summary is None 判定原始事实完全未保存；同时 raw_archive 再失败会向外传播。

7. AutoCompact._split_unconsolidated / check_expired

空闲整理只归档能安全切走的前缀，并主动避开正在对话的会话。

当前源码原文 · nanobot/agent/autocompact.py · AutoCompact._split_unconsolidated / check_expired · 第 40–72 行（连续摘录）

    def _split_unconsolidated(
        self, session: Session,
    ) -> tuple[list[dict[str, Any]], list[dict[str, Any]]]:
        """Split live session tail into archiveable prefix and retained recent suffix."""
        tail = list(session.messages[session.last_consolidated:])
        if not tail:
            return [], []

        probe = Session(
            key=session.key,
            messages=tail.copy(),
            created_at=session.created_at,
            updated_at=session.updated_at,
            metadata={},
            last_consolidated=0,
        )
        probe.retain_recent_legal_suffix(self._RECENT_SUFFIX_MESSAGES)
        kept = probe.messages
        cut = len(tail) - len(kept)
        return tail[:cut], kept

    def check_expired(self, schedule_background: Callable[[Coroutine], None],
                      active_session_keys: Collection[str] = ()) -> None:
        """Schedule archival for idle sessions, skipping those with in-flight agent tasks."""
        now = datetime.now()
        for info in self.sessions.list_sessions():
            key = info.get("key", "")
            if not key or key in self._archiving:
                continue
            if key in active_session_keys:
                continue
            if self._is_expired(info.get("updated_at"), now):
                self._archiving.add(key)
  1. tail 取 messages[last_consolidated:]；复制到临时 Session probe，调用 retain_recent_legal_suffix(8) 得到合法最近后缀。8 是目标，不是任意切掉第九条。
  2. 用 tail 总长减 kept 长得到 cut，返回 archiveable prefix 与 kept suffix；原 Session 在此处尚未修改。
  3. check_expired 遍历会话，跳过无 key、已在 _archiving、在 active_session_keys 中的条目；过期后先登记 _archiving 再调度后台任务，避免重复排队。

8. SessionManager.save

Session 保存同时写元数据与消息，它的原子替换保证与可选 durability 要分开理解。

当前源码原文 · nanobot/session/manager.py · SessionManager.save · 第 423–470 行（连续摘录）

    def save(self, session: Session, *, fsync: bool = False) -> None:
        """Save a session to disk atomically.

        When *fsync* is ``True`` the final file and its parent directory are
        explicitly flushed to durable storage.  This is intentionally off by
        default (the OS page-cache is sufficient for normal operation) but
        should be enabled during graceful shutdown so that filesystems with
        write-back caching (e.g. rclone VFS, NFS, FUSE mounts) do not lose
        the most recent writes.
        """
        path = self._get_session_path(session.key)
        tmp_path = path.with_suffix(".jsonl.tmp")

        try:
            with open(tmp_path, "w", encoding="utf-8") as f:
                metadata_line = {
                    "_type": "metadata",
                    "key": session.key,
                    "created_at": session.created_at.isoformat(),
                    "updated_at": session.updated_at.isoformat(),
                    "metadata": session.metadata,
                    "last_consolidated": session.last_consolidated
                }
                f.write(json.dumps(metadata_line, ensure_ascii=False) + "\n")
                for msg in session.messages:
                    f.write(json.dumps(msg, ensure_ascii=False) + "\n")
                if fsync:
                    f.flush()
                    os.fsync(f.fileno())

            os.replace(tmp_path, path)

            if fsync:
                # fsync the directory so the rename is durable.
                # On Windows, opening a directory with O_RDONLY raises
                # PermissionError — skip the dir sync there (NTFS
                # journals metadata synchronously).
                with suppress(PermissionError):
                    fd = os.open(str(path.parent), os.O_RDONLY)
                    try:
                        os.fsync(fd)
                    finally:
                        os.close(fd)
        except BaseException:
            tmp_path.unlink(missing_ok=True)
            raise

        self._cache[session.key] = session
  1. 第一行记录 key、时间、metadata 和 last_consolidated，之后每行一条消息。将游标与消息存在同一文件，可让载入读取同版本。
  2. 默认 fsync=False，不强制刷盘；显式 fsync=True 时先同步临时文件，再 replace，再尝试目录同步。原子可见性和掉电持久性不是同一性质。
  3. 失败清理 tmp 并抛出。最后才更新内存 cache；若外部还持有已修改的 Session 对象，不能简单认为异常就恢复了旧内存内容。

用一组具体数据推演全部变化

准备 Session 消息序列 [u1,a1,u2,a2,u3,a3]，last_consolidated=0。为便于手算，把每条消息 token 估算固定成 [10,20,10,20,10,20]，希望去掉至少 45 token。history 当前最大 cursor=40，Dream 已处理 cursor=40。以下 token 是练习假计数器，不是实际 tokenizer 结果。

操作计算状态
选归档边界idx2 遇 u2，累计30<45；idx4 遇u3，累计60≥45返回 (4,60)，归档 [u1,a1,u2,a2]，保留 [u3,a3]。
摘要成功append_history("用户研究异步队列")新增 cursor41；上层成功归档后推进 Session 下标到4，摘要可作为压缩上下文。
又归档一批追加 cursor42Dream 待处理列表为 [41,42]；设 max_batch_size=1，本次只取41。
Dream Phase1得出新增偏好的分析游标仍40，文件尚不因分析文字自动改变。
Dream Phase2 部分失败edit_file 成功一次，后续停止原因 max_iterations长期文件可能变化，Dream 游标仍40；下次再次处理41，需要去重。

独立搭建本章最小模块

从零实现 MiniMemoryPipeline，仅使用练习目录中的 JSONL 与 Markdown 文件。输入是带角色的 Session 消息和固定 token 估算；输出是归档记录、更新后的 Session 下标、Dream 消费游标。假 summarizer 可抛错，假 editor 可模拟“完成”“部分编辑后失败”。不调用真实模型。

展开参考方案：结构、算法与错误处理
  1. 把 Session 下标与 history 全局 cursor 定义为不同字段/类型，函数名明确区分 mark_consolidated(index) 与 advance_dream(cursor)。
  2. 按 user 边界累计 token 选择前缀。summarize 成功写摘要；失败保存有长度上限的原文；只有归档写入成功后才移动 Session 边界。
  3. 读 JSONL 时跳过损坏行并保留有效 cursor；生成 cursor 要考虑现有记录最大值与侧文件值。不要在裁剪后把 cursor 从 1 重来。
  4. 整体压缩写入同目录 tmp，flush+fsync 后 replace；故障注入点放在 replace 前，验证旧文件还可读。不要把演示中的假路径指向实际用户记忆。
  5. Dream 只处理 since_cursor 之后的最多 N 条；完成后前移到 batch[-1].cursor，失败保留。以稳定事实键去重，例如 preference:language，使同批重放不会重复追加。

验收条件

  1. 固定 [10,20,10,20,10,20] 输入得到 boundary=4、removed=60；最后一轮保持完整。
  2. 摘要失败仍有受限 raw 记录；写入也失败时 Session 边界不前移。
  3. Dream 部分编辑失败保持旧游标，重试成功后只有一个相同事实条目。
  4. 整体重写在 replace 前失败，旧 JSONL 内容逐字不变且 tmp 清理；history 裁剪后 cursor 仍单调。

边界、不变量与容易写错的地方

  1. Session.messages 下标不等于 history.cursor，更不等于时间戳。三个标识分别解决回放范围、增量消费、时间语义。
  2. Dream 的“completed 才推进”不能保证所有文件修改 exactly once；崩溃可能发生在编辑成功与写 cursor 之间。避免重复写事实要靠幂等编辑。
  3. 摘要是有损表示，不应无上限回填原始消息作为兜底；否则归档反而扩大下一轮 prompt。
  4. MemoryStore 的整体 history 重写有原子替换；append_history、Dream cursor 写入有不同保证。阅读注释时必须对准具体函数。
  5. 文件工具的允许目录与安全限制仍适用于 Dream 编辑；不能因为是后台记忆整理就绕过 _resolve_path。
  6. 本章验收只需要假 summarizer/editor；如扩展为真实 LLM，仍必须使用 deepseek-v4-flash 并遵守项目凭据读取约束。
