for _, module_name, _ in pkgutil.iter_modules(package.__path__):
    if module_name.startswith("_") or module_name in _SKIP_MODULES:
        continue

results.sort(key=lambda cls: cls.__name__)

base/schema/registry/context/loader/mcp 等基础模块被跳过；私有类、抽象类和 _plugin_discoverable=False 的特殊 wrapper 也不会误注册。模块导入失败只记录日志并继续扫描其他模块。

entry point 只负责定位一个 Tool 类。它不会绕过 Tool 契约：插件仍要经过 scope、enabled/create、名称冲突处理、Registry 参数校验和 Runner 执行策略。

加载阶段的决策顺序

→→→→

先内置，后插件

Loader 保留 builtin_names，用于保护核心工具名称；发现结果在 Loader 实例中缓存。

_scopes 控制运行环境

默认只属于 core；文件读取可同时供 core/subagent/memory，Shell/Web 可供 core/subagent，避免子 Agent 或 Dream 获得不必要能力。

enabled(ctx)

根据配置与依赖决定是否出现。例如 CronService 不存在时 CronTool 不注册，exec/web/image generation 可由配置关闭。

create(ctx)

通过 ToolContext 注入 workspace、bus、subagent manager、cron service、Provider 配置和 timezone；每个 Registry 得到独立实例。

内置名称优先

插件与内置同名时插件被跳过；其他同名碰撞会告警并由后注册实例覆盖。随后 Registry 缓存失效。

构造期与请求期是两种 Context

ToolContext：构造依赖

AgentLoop 启动注册时传入 config、workspace、bus、subagent manager、cron service、Provider loader、image provider configs 与 timezone。Tool 的 create() 用它建立长期实例。

RequestContext：本轮路由

每条消息进入 BUILD 和工具执行前，Loop 注入 channel、chat_id、message_id、session_key 与 metadata。只有实现 ContextAware Protocol 的工具接收它。

agent/loop.py:532为共享 Registry 写入当前请求上下文
request_ctx = RequestContext(
    channel=channel,
    chat_id=chat_id,
    message_id=message_id,
    session_key=effective_key,
    metadata=dict(metadata or {}),
)
for name in self.tools.tool_names:
    tool = self.tools.get(name)
    if isinstance(tool, ContextAware):
        tool.set_context(request_ctx)

Message、Spawn、Cron 等工具必须知道结果发回哪里。它们使用 ContextVar 保存请求期值，使同一工具实例在并发 asyncio task 中保持上下文隔离；文件读写状态也通过独立的 context binding 按 Session 隔离。

自测

  • 第三方插件与内置 read_file 同名时会发生什么？
    查看答案收起答案

    ToolLoader 先登记内置名称；加载 entry-point 插件时若发现它与内置 read_file 同名，会记录 warning 并直接跳过该插件，因此内置实现不会被覆盖。

  • 为什么 ToolContext 不能替代每轮 RequestContext？
    查看答案收起答案

    ToolContext 是装配期共享依赖，如 workspace、配置和服务；每轮 RequestContext 还包含当前 channel/chat/sender/session。后者必须请求级隔离，不能固定在长期 Tool 实例上。

  • scope 如何落实最小权限，而不只是一种分类标签？
    查看答案收起答案

    Loader 读取 Tool 类的 _scopes，只在请求的 core/subagent/memory scope 包含时实例化注册。未进入 Registry 的工具不会出现在 schema，也不能被该 Runner 按名称执行。
