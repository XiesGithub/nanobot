MCP Tool、Resource 与 Prompt 的统一适配

MCP 暴露三类 capability，但 AgentRunner 只认识 nanobot Tool。三个 Wrapper 把远程调用、资源读取和 Prompt 获取全部适配为相同的 name/description/parameters/execute 契约。

Tool Wrapper 的适配过程

→→→→

原始名只用于 MCP RPC

_original_name 保留 Server 定义，实际调用仍传它，避免 Provider 兼容处理改变远程协议标识。

包装名避免跨 Server 碰撞

前缀加入 server name；非字母数字、下划线和连字符替换为下划线，并折叠连续下划线，以兼容 OpenAI/Anthropic 工具名限制。

只做窄范围 Schema 兼容

type: [T, null] 与单一 nullable oneOf/anyOf 被转换为 type=T + nullable；properties/items 递归处理，不任意重写远程约束。

超时包裹真正 RPC

asyncio.wait_for(call_tool(...), tool_timeout)；参数已在本地 Registry 按归一后 Schema 验证。

结果转为文本

TextContent 取 text，其他 block 转字符串，多块用换行连接；空内容返回显式 (no output)。

enabledTools 的准确边界

agent/tools/mcp.py:524只过滤 list_tools 结果
enabled = set(cfg.enabled_tools)
allow_all = "*" in enabled

for tool_def in tools.tools:
    wrapped = sanitize(f"mcp_{server}_{tool_def.name}")
    if not allow_all and tool_def.name not in enabled and wrapped not in enabled:
        continue
    registry.register(MCPToolWrapper(...))
  • ["*"]：默认注册所有 MCP tools。
  • 原始名称或包装名称：两种写法都能精确启用某个 tool。
  • 空列表：不注册任何 tools。
  • 未知条目：记录可用 raw/wrapped 名称，便于纠错。
当前实现细节：enabledTools 只应用于 MCP Tools；连接成功后发现的 Resources 和 Prompts 会全部尝试注册。若需要限制它们，应在 MCP Server 端控制暴露范围或扩展客户端配置。

失败与取消语义

失败处理给 Agent 的结果
调用超过 tool_timeoutwait_for 超时，立即返回(MCP ... timed out after Ns)
连接断开类瞬态异常等待 1 秒，最多重试 1 次第二次失败返回异常类型
MCP SDK 泄漏 CancelledError当前 task 没有外部 cancelling 时转成失败文本(MCP ... was cancelled)
用户 /stop 或系统真正取消 tasktask.cancelling() > 0 时重新抛出沿 AgentLoop 取消/Checkpoint 路径处理
Prompt McpError记录 code/message返回含服务端错误码的失败文本
其他异常记录完整日志，隐藏内部细节只暴露异常类型

Resource 与 Prompt 的输出转换

Resource

TextResourceContents 返回正文；BlobResourceContents 不把二进制塞进 Context，只返回字节数占位；其他类型转字符串。

Prompt

遍历返回 messages；TextContent 取正文，list 中逐块提取。它返回“可作为工作流指南的文本”，不会直接替换 system prompt。

for attempt in range(2):
    try:

            raise
        return "(MCP call was cancelled)"

            await asyncio.sleep(1)
            continue
        return "(MCP call failed: ExceptionType)"

自测

  • MCP 原始工具名和模型看到的包装名为什么必须分开保存？
    查看答案收起答案

    模型名通常加服务器前缀以避免多个 MCP 服务同名，而协议调用必须发送服务声明的原始 name。包装器同时保存两者，Registry 用包装名路由，MCP session 用原名调用。

  • 为什么 MCP Resource 的二进制内容只返回大小占位？
    查看答案收起答案

    LLM tool result 是文本通道，直接内联任意二进制既无法可靠解释又可能造成巨大上下文。包装器只报告 MIME/大小等占位信息，实际二进制应通过专门文件或媒体路径处理。

  • 如何区分 MCP SDK 内部取消与用户真正执行 /stop？
    查看答案收起答案

    执行 wrapper 捕获 CancelledError 后检查当前 task 是否真的处于 cancelling 状态；若是则重新抛出保留 /stop，否则把 MCP/anyio 泄漏的内部取消转换为普通工具错误。
