最小 Tool 接口

agent/tools/base.py:124四个抽象成员
class Tool(ABC):
    @property
    @abstractmethod
    def name(self) -> str: ...

    @property
    @abstractmethod
    def description(self) -> str: ...

    @property
    @abstractmethod
    def parameters(self) -> dict[str, Any]: ...

    @abstractmethod
    async def execute(self, **kwargs: Any) -> Any: ...

name 是模型调用和 Registry 查找的主键；description 影响模型何时选择它；parameters 是输入协议；execute 才是实际副作用。Tool 并不依赖特定 Provider。

从 Tool 到 Provider Schema

agent/tools/base.py:216OpenAI function 形状
def to_schema(self):
    return {
        "type": "function",
        "function": {
            "name": self.name,
            "description": self.description,
            "parameters": self.parameters,
        },
    }

Runner 把这些 definitions 交给 Provider；其他 Provider 实现可在自己的适配层转换协议。核心工具层保持一种稳定形状。

Schema 同时服务三件事

Guide
告诉模型字段名称、类型、描述、枚举和必填项
Cast
把模型常见的 "42"、"true" 安全转换为 int/bool
Guard
在 execute 前验证类型、范围、长度、嵌套对象与数组

为什么先 cast 再 validate

→→→

原始参数不完全可靠

模型可能把整数或布尔值写成字符串，也可能给出 list 而非 object、漏掉 required，或越过 minimum/maximum。

转换是保守的

只转换 Schema 明确声明的 string/integer/number/boolean，以及数组元素和嵌套对象；单值不会自动包成数组，无法转换的值原样保留。

错误一次性收集

validate_json_schema_value 返回字符串列表而非立即抛出，模型能同时看到多个字段问题并在下一 iteration 修正。

execute 获得结构化输入

Registry 只在错误列表为空时返回可执行 Tool；业务代码不必重复处理最基础的 JSON 类型错误。

两种声明参数的方式

直接 JSON Schema

Tool 实现 parameters property，返回 object/properties/required。适合已有外部 Schema 或复杂结构。

Schema 类与装饰器

StringSchema、IntegerSchema、ArraySchema、ObjectSchema 组合后，由 @tool_parameters 注入深拷贝 property，防止调用者修改类级定义。

自测

  • description 写得含糊会影响执行代码，还是影响模型选择？
    查看答案收起答案

    主要影响模型是否理解并选择该工具、以及参数如何生成；Python 执行函数本身不会因描述含糊而改变。但错误选择会间接导致无效或危险调用。

  • 为什么不能把任意单值自动包成 array？
    查看答案收起答案

    单值变数组会掩盖模型的结构错误，也无法判断目标是一个元素还是错误编码。当前 cast 只做 schema 明确且安全的标量转换，array 必须由模型真正提供列表。

  • exclusive=True 与 read_only=True 同时出现时能否并发？
    查看答案收起答案

    不能。concurrency_safe 的默认判定是 read_only and not exclusive；exclusive 明确要求独占，即使工具声明只读也会被串行调度。
