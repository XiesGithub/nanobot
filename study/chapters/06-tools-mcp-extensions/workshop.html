先约定谁持有数据、谁可以改变数据

Tool 是能力契约，Loader 是装配政策，Registry 是运行时映射，Runner 是调度策略。MCP 只是其中一种执行适配方式。

1. 参数校验把模型字符串变成可检验的输入

工具不应假设模型总能按 schema 输出正确类型。该校验器返回一组错误，而不是直接执行能力。

当前源码原文：nanobot/agent/tools/base.py · Schema.validate_json_schema_value · 第 48–101 行（连续摘录）
    def validate_json_schema_value(val: Any, schema: dict[str, Any], path: str = "") -> list[str]:
        """Validate ``val`` against a JSON Schema fragment; returns error messages (empty means valid).

        Used by :class:`Tool` and each concrete Schema's :meth:`validate_value`.
        """
        raw_type = schema.get("type")
        nullable = (isinstance(raw_type, list) and "null" in raw_type) or schema.get("nullable", False)
        t = Schema.resolve_json_schema_type(raw_type)
        label = path or "parameter"

        if nullable and val is None:
            return []
        if t == "integer" and (not isinstance(val, int) or isinstance(val, bool)):
            return [f"{label} should be integer"]
        if t == "number" and (
            not isinstance(val, _JSON_TYPE_MAP["number"]) or isinstance(val, bool)
        ):
            return [f"{label} should be number"]
        if t in _JSON_TYPE_MAP and t not in ("integer", "number") and not isinstance(val, _JSON_TYPE_MAP[t]):
            return [f"{label} should be {t}"]

        errors: list[str] = []
        if "enum" in schema and val not in schema["enum"]:
            errors.append(f"{label} must be one of {schema['enum']}")
        if t in ("integer", "number"):
            if "minimum" in schema and val < schema["minimum"]:
                errors.append(f"{label} must be >= {schema['minimum']}")
            if "maximum" in schema and val > schema["maximum"]:
                errors.append(f"{label} must be <= {schema['maximum']}")
        if t == "string":
            if "minLength" in schema and len(val) < schema["minLength"]:
                errors.append(f"{label} must be at least {schema['minLength']} chars")
            if "maxLength" in schema and len(val) > schema["maxLength"]:
                errors.append(f"{label} must be at most {schema['maxLength']} chars")
        if t == "object":
            props = schema.get("properties", {})
            for k in schema.get("required", []):
                if k not in val:
                    errors.append(f"missing required {Schema.subpath(path, k)}")
            for k, v in val.items():
                if k in props:
                    errors.extend(Schema.validate_json_schema_value(v, props[k], Schema.subpath(path, k)))
        if t == "array":
            if "minItems" in schema and len(val) < schema["minItems"]:
                errors.append(f"{label} must have at least {schema['minItems']} items")
            if "maxItems" in schema and len(val) > schema["maxItems"]:
                errors.append(f"{label} must be at most {schema['maxItems']} items")
            if "items" in schema:
                prefix = f"{path}[{{}}]" if path else "[{}]"
                for i, item in enumerate(val):
                    errors.extend(
                        Schema.validate_json_schema_value(item, schema["items"], prefix.format(i))
                    )
        return errors
  1. 读取 type 和 nullable，明确允许的 null 才提前通过。整数/数值专门排除 bool，因为 Python 中 bool 是 int 的子类。
  2. 类型通过后检查 enum、范围和长度约束；对象检查 required，再递归检查已声明属性。错误路径可包含嵌套字段名。
  3. 数组验证项数与每个 item，最终返回 errors；空数组意味着没有发现错误，不是“验证未运行”。

取舍与异常边界：这是一套局部 JSON Schema 支持，不是完整规范实现。此段只递归 props 中的字段，不能据此声称会拒绝所有未知参数；复杂 oneOf 等需额外逻辑。

2. 工具集合同时也是稳定提示词的一部分

注册表不仅查名字，还把运行时对象变成发给 Provider 的定义列表。稳定顺序能减少无意义的提示词变动。

当前源码原文：nanobot/agent/tools/registry.py · ToolRegistry.get_definitions · 第 48–71 行（连续摘录）
    def get_definitions(self) -> list[dict[str, Any]]:
        """Get tool definitions with stable ordering for cache-friendly prompts.

        Built-in tools are sorted first as a stable prefix, then MCP tools are
        sorted and appended.  The result is cached until the next
        register/unregister call.
        """
        if self._cached_definitions is not None:
            return self._cached_definitions

        definitions = [tool.to_schema() for tool in self._tools.values()]
        builtins: list[dict[str, Any]] = []
        mcp_tools: list[dict[str, Any]] = []
        for schema in definitions:
            name = self._schema_name(schema)
            if name.startswith("mcp_"):
                mcp_tools.append(schema)
            else:
                builtins.append(schema)

        builtins.sort(key=self._schema_name)
        mcp_tools.sort(key=self._schema_name)
        self._cached_definitions = builtins + mcp_tools
        return self._cached_definitions
  1. 缓存存在时直接返回；register/unregister 负责使缓存失效。工具对象属性自行变化不会自动触发这一机制。
  2. 将 to_schema() 结果按名字前缀分为 builtin 与 mcp_ 两组，分别排序。
  3. 将 builtin 作为稳定前缀、MCP 接在后面并保存缓存。该分类依赖名称，不依赖 Python 类的来源证明。

取舍与异常边界：缓存提高效率但返回共享列表，调用者不应原地修改。mcp_ 命名是表示约定，不是安全认证，也不是服务能力授权。

3. 名字解析、转换、校验和执行各有边界

一条模型调用通常只有 name 与 params。prepare_call 把这两项转为可执行工具对象和经过处理的参数。

当前源码原文：nanobot/agent/tools/registry.py · ToolRegistry.prepare_call / execute · 第 73–114 行（连续摘录）
    def prepare_call(
        self,
        name: str,
        params: dict[str, Any],
    ) -> tuple[Tool | None, dict[str, Any], str | None]:
        """Resolve, cast, and validate one tool call."""
        # Guard against invalid parameter types (e.g., list instead of dict)
        if not isinstance(params, dict) and name in ('write_file', 'read_file'):
            return None, params, (
                f"Error: Tool '{name}' parameters must be a JSON object, got {type(params).__name__}. "
                "Use named parameters: tool_name(param1=\"value1\", param2=\"value2\")"
            )

        tool = self._tools.get(name)
        if not tool:
            return None, params, (
                f"Error: Tool '{name}' not found. Available: {', '.join(self.tool_names)}"
            )

        cast_params = tool.cast_params(params)
        errors = tool.validate_params(cast_params)
        if errors:
            return tool, cast_params, (
                f"Error: Invalid parameters for tool '{name}': " + "; ".join(errors)
            )
        return tool, cast_params, None

    async def execute(self, name: str, params: dict[str, Any]) -> Any:
        """Execute a tool by name with given parameters."""
        _HINT = "\n\n[Analyze the error above and try a different approach.]"
        tool, params, error = self.prepare_call(name, params)
        if error:
            return error + _HINT

        try:
            assert tool is not None  # guarded by prepare_call()
            result = await tool.execute(**params)
            if isinstance(result, str) and result.startswith("Error"):
                return result + _HINT
            return result
        except Exception as e:
            return f"Error executing {name}: {str(e)}" + _HINT
  1. read_file/write_file 遇到非对象参数先返回清晰错误；工具名不存在则列出可用名字。注意这个顶层特判只针对这两个工具。
  2. 先 cast_params 再 validate_params：例如 schema 允许的安全数字转换可先完成。错误返回三元组中的 error，调用者不应继续执行。
  3. execute 遇到准备错误直接返回带修正提示的文字；真正 tool.execute(**params) 在 try 中执行，异常被转成错误文字，已有 Error 前缀结果也追加提示。

取舍与异常边界：prepare_call 在 execute 的 try 外部，cast/validate 自身抛异常不受下面 except 捕获。Runner 还有自己的 _run_tool 调度与错误策略，不能认为它简单无条件调用本段 execute。

4. 发现类不代表允许实例化进本轮

Loader 根据 scope 和 enabled 决定装入哪些工具，Registry 专注名字到对象的映射。

当前源码原文：nanobot/agent/tools/loader.py · ToolLoader.load · 第 86–116 行（连续摘录）
    def load(self, ctx: Any, registry: ToolRegistry, *, scope: str = "core") -> list[str]:
        registered: list[str] = []
        builtin_names: set[str] = set()
        sources = [(self.discover(), False), (self._discover_plugins().values(), True)]
        for source, is_plugin_source in sources:
            for tool_cls in source:
                cls_label = tool_cls.__name__
                try:
                    if scope not in getattr(tool_cls, "_scopes", {"core"}):
                        continue
                    if not tool_cls.enabled(ctx):
                        continue
                    tool = tool_cls.create(ctx)
                    if registry.has(tool.name):
                        if is_plugin_source and tool.name in builtin_names:
                            logger.warning(
                                "Plugin %s skipped: conflicts with built-in tool %s",
                                cls_label, tool.name,
                            )
                            continue
                        logger.warning(
                            "Tool name collision: %s from %s overwrites existing",
                            tool.name, cls_label,
                        )
                    registry.register(tool)
                    registered.append(tool.name)
                    if not is_plugin_source:
                        builtin_names.add(tool.name)
                except Exception:
                    logger.error("Failed to register tool: %s", cls_label)
        return registered
  1. 先遍历内置发现结果，再遍历入口点插件；scope 不匹配或 enabled 为假直接跳过。
  2. 用 ToolContext 调用 create；若插件名字与已装入内置工具冲突，跳过插件，保护内置名字。
  3. 其他重名记录警告后覆盖；成功注册使 schema 缓存失效。一个工具初始化异常被隔离，继续装入其他工具。

取舍与异常边界：“Registry.register 会覆盖”与“插件不能覆盖内置工具”不矛盾，后者是 Loader 的政策。绕过 Loader 直接注册时，不能假装仍享有相同冲突保护。

5. 远程能力被适配成本地 Tool 契约

Wrapper 分离模型可见名称与服务器原始名称，使 Provider 命名限制不泄漏到远程协议。

    async def execute(self, **kwargs: Any) -> str:
        from mcp import types

        for attempt in range(2):  # At most 1 retry
            try:
                result = await asyncio.wait_for(
                    self._session.call_tool(self._original_name, arguments=kwargs),
                    timeout=self._tool_timeout,
                )
            except asyncio.TimeoutError:
                logger.warning(
                    "MCP tool '{}' timed out after {}s", self._name, self._tool_timeout
                )
                return f"(MCP tool call timed out after {self._tool_timeout}s)"
            except asyncio.CancelledError:
                # MCP SDK's anyio cancel scopes can leak CancelledError on timeout/failure.
                # Re-raise only if our task was externally cancelled (e.g. /stop).
                task = asyncio.current_task()
                if task is not None and task.cancelling() > 0:
                    raise
                logger.warning("MCP tool '{}' was cancelled by server/SDK", self._name)
                return "(MCP tool call was cancelled)"
  1. 模型看到清洗后的 mcp_server_tool 名；真正调用服务器时使用 _original_name。inputSchema 被规范化后通过 parameters 属性暴露。
  2. execute 用 wait_for 包住远程 call_tool；超时转为可读字符串。该字符串没有 Error 前缀，不能用 Registry 的前缀规则概括全部远程失败。
  3. CancelledError 特别区分：当前任务正在被外部取消时重新抛出，让 /stop 生效；否则把 SDK/服务端泄漏的取消信号变为失败文本。

取舍与异常边界：只有 wrapper 对象共享 Session，并不等于远程工具无副作用。MCPToolWrapper 未在这里声明 read_only，不能默认把所有远程调用并行化。

6. 有限重试与结果降维

远程调用既可能失败，也可能返回异构内容块。Wrapper 需要把这些形状收敛为当前 Tool 的结果。

手工演算：消息和状态如何一步步变化

设计一个教学工具 scale：参数 n 是 integer 且 minimum=1，返回 n×2。注册 read_file、scale 与 mcp_docs_search 后，模拟调用 {id:"c7",name:"scale",arguments:{n:"3"}}。这里的 scale 只是练习工具，不冒充当前内置能力。

步骤状态 / 数据推导
注册_tools 含三个对象；_cached_definitions=None每次注册都使缓存失效
取定义[read_file,scale,mcp_docs_search]内置按名排序，MCP 独立排在后面
准备 c7name=scale；params={n:"3"}→{n:3}cast 根据 schema 转换；validate 返回 []
执行await scale.execute(n=3)→"6"一次调用产生一个结果
回填role=tool,tool_call_id=c7,name=scale,content="6"模型下一轮同时看到 c7 声明与结果
失败变体n=0→minimum 错误；name=scael→未找到两种情况执行次数都为 0；模型得到修正反馈

再把结果换成远程 MCP：连接第一次 BrokenPipeError、第二次返回两个 TextContent("a","b")，最终为 "a\nb"，远程尝试次数为 2；若第一次超时则直接返回超时文本，次数为 1。外部取消必须继续向上冒泡。

从空文件实现一个可推演的最小模块

实现一个内存工具注册表和模拟远程适配器。练习目标是验证边界与错误传播，不需要安装 MCP 服务器。

  1. 建立 Tool 接口：name、parameters、cast、validate、execute；注册表支持注册/注销和稳定 schema 缓存。
  2. 实现 scale 的 integer/minimum 验证，避免把 bool 接受成整数；名字解析失败和参数失败不得进入 execute。
  3. 实现 FakeSession 的脚本化结果序列，分别模拟一次瞬时连接错误、超时和外部取消；给每次远程尝试计数。

将 I/O 放在可替换的回调中，用固定输入验证状态与调用次数；错误路径必须留下可观察的结果，不能只写日志。

验收条件

  1. n="3" 得到 6；n=0、n=true、缺 n 都不执行；错误中能定位 n。
  2. 注销 scale 后 schema 中不再包含它；重复取定义保持顺序，不改变缓存内容。
  3. 瞬时失败最多调用 2 次，超时只调用 1 次，外部取消保持取消状态。
  4. 为写工具明确禁用并发；说明为什么服务端幂等比客户端重试次数更能防止重复写入。

边界、不变量与容易写错的地方

  1. 参数类型检查不能替代安全边界。文件工具仍须 _resolve_path 校验 allowed_dir；网络工具仍须 validate_url_target 防 SSRF。
  2. 不要把“schema 可见”当作“调用安全”。description 和工具返回内容也会进入后续提示词，需避免泄漏内部敏感信息。
  3. 同名覆盖政策由调用路径决定：直接 Registry.register 与 ToolLoader 插件装配的行为不同。
  4. MCP Resource/Prompt 的 read_only 与通用 MCP Tool 默认权限不同，不能按 mcp_ 前缀统一并发。
  5. 新增能力优先位于工具或 MCP 边缘，避免为了一个新工具修改核心 Loop/Runner。

独立推理练习

  1. 为何 validate 在 execute 前仍不能保证没有异常？
    展开推理依据

    cast/validate 本身可能抛异常，远程连接也可能失败；准备结果与执行异常是两个边界。

  2. 为什么要保留 original_name？
    展开推理依据

    模型可见名称经过清洗和命名空间拼接，服务器仍只认识原始 tool 名。

  3. 重试一次就能保证不会重复写吗？
    展开推理依据

    不能。首次调用可能完成写入后连接断开；需要远端幂等或可确认的操作状态。
