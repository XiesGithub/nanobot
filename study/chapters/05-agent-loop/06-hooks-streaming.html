它不是 Session 或 TurnContext：生命周期仅覆盖 Runner 的一次 iteration，字段由 Runner 随执行推进写入，Hook 读取同一份状态以生成进度、日志或捕获结果。

LoopHook 把 Runner 事件翻译成渠道能力

→→→

跨 chunk 过滤 think

_stream_buf 累计原始 delta，每次比较清理前后的长度，只发送新增可见部分，避免 <think> 跨 chunk 时泄漏。

结构化工具事件

工具执行前发送 start payload，之后发送 success/error/waiting payload；老式 progress callback 仍可只接收文本 hint。

共享 ToolRegistry，隔离请求上下文

LoopHook 在执行前写入 channel、chat、message、metadata、session_key；ContextAware 工具据此正确投递消息或创建子任务。

每 iteration 记录 usage

Hook 打印单次原始 usage；Runner 另外累计整次运行的 prompt/completion tokens，最终交回 AgentLoop。

CompositeHook 的错误隔离策略

agent/hook.py:58核心 Hook + 扩展 Hook
hook = CompositeHook([loop_hook] + self._extra_hooks)

for hook in self._hooks:
    if hook._reraise:
        await hook.method(...)
    else:
        try:
            await hook.method(...)
        except Exception:
            logger.exception(...)

# finalize_content 是有顺序的同步 pipeline
for hook in self._hooks:
    content = hook.finalize_content(context, content)

自定义 Hook 的异步副作用失败不会拖垮 Agent；核心 _LoopHook 使用 reraise=True，因为渠道流式投递和工具上下文绑定属于主路径。内容变换则不吞异常，避免悄悄返回错误文本。

流式输出为什么有 segment

_dispatch() 为每个片段生成 stream_base_id:segment。模型发出工具调用时，Runner 用 resuming=True 结束当前片段，渠道可以结束当前渲染但继续显示加载；最终答案用 resuming=False 真正收尾。

三个观测层级

Turn
turn_id + StateTraceEntry：定位 RESTORE/BUILD/RUN/SAVE 哪一段慢
Iteration
HookContext：模型响应、工具调用、工具事件与单轮 usage
Run
AgentRunResult：累计 usage、tools_used、stop_reason、error

SDKCaptureHook 展示了最小扩展模式

SDKCaptureHook 只在 after_iteration 中收集工具名，并刷新 messages 快照。它不需要让 Runner 增加 “if SDK” 分支，说明 Hook 边界可以承载额外消费者，同时保持核心循环小而稳定。

Hook 不是修改控制流的状态机：它适合观察、转换内容和侧向通知；是否继续 iteration、如何执行工具、怎样停止仍由 Runner 掌握。把关键控制流藏进 Hook 会使恢复和测试语义难以追踪。

自测

  • 为什么 LoopHook 而不是 Runner 负责过滤并投递 stream delta？
    查看答案收起答案

    Runner 只产生 delta 事件；是否支持流式、如何标记 thread、过滤内部/重复文本以及发布到 MessageBus 都属于渠道语义。LoopHook 持有消息 origin，最适合完成这层适配。

  • resuming=True 对渠道 UI 表示什么？
    查看答案收起答案

    它告诉渠道这段流是在已有消息/中断上下文之后恢复，而非一条全新响应。支持该 metadata 的 UI 可继续原流或采用不同状态提示。

  • 自定义 Hook 抛异常时，哪些异常被隔离，哪些会暴露？
    查看答案收起答案

    Hook 汇聚器对普通观察型回调异常做日志隔离，避免监控拖垮 Agent；代表用户取消的 CancelledError 和核心 checkpoint/执行路径要求保留的控制异常不会被伪装成成功。
