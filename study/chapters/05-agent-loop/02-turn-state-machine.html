先区分三个层次

函数生命周期主要职责
run()进程级，直到 stop/shutdown消费输入、空闲检查、命令快速通道、创建 task 或注入 pending queue
_dispatch()一次被调度任务Session lock、全局 gate、stream 适配、异常兜底、发布输出、清理 pending queue
_process_message()一次 Turn驱动 RESTORE→…→DONE 状态机并记录每个阶段耗时

事件泵为什么创建 task

agent/loop.py:867简化后的主循环
while self._running:
    msg = await asyncio.wait_for(self.bus.consume_inbound(), timeout=1.0)

    if self.commands.is_priority(msg.content.strip()):
        await self._dispatch_command_inline(...)
        continue

    if effective_key in self._pending_queues:
        self._pending_queues[effective_key].put_nowait(msg)
        continue

    task = asyncio.create_task(self._dispatch(msg))
    self._active_tasks.setdefault(effective_key, []).append(task)

如果主循环直接 await _dispatch()，模型调用期间就无法及时消费后续的 /stop。创建 task 后，主循环仍能读取 Bus；优先命令可直接取消正在运行的 task，同 Session 普通消息则注入当前 Turn。

Turn 状态图

→→→→→→

RESTORE

提取文档；获取 Session；恢复 runtime checkpoint 与只有 user、没有 assistant 的未完成 Turn。

COMPACT

AutoCompact.prepare_session() 重新加载 Session，并取出需要注入下一轮的 archived summary。

COMMAND

普通命令若被 CommandRouter 处理，返回 shortcut 直接进入 DONE，不构建 Prompt 也不请求 LLM。

BUILD

执行 token consolidation、绑定工具上下文、选取 history、构造 initial messages，并尽早持久化用户输入。

RUN

把 initial messages、工具、Hook、checkpoint 与 injection callback 交给 AgentRunner。

SAVE

补全空响应、提取生成图片、只保存本轮新增消息、清 checkpoint，并后台触发下一轮 consolidation 检查。

RESPOND

处理 MessageTool 抑制、ask_user 按钮、streamed 标志和媒体，生成最终 OutboundMessage。

显式 transition table

agent/loop.py:252状态 + 事件 → 下一状态
_TRANSITIONS = {
    (RESTORE, "ok"): COMPACT,
    (COMPACT, "ok"): COMMAND,
    (COMMAND, "dispatch"): BUILD,
    (COMMAND, "shortcut"): DONE,
    (BUILD, "ok"): RUN,
    (RUN, "ok"): SAVE,
    (SAVE, "ok"): RESPOND,
    (RESPOND, "ok"): DONE,
}

处理器不直接修改下一个状态，只返回业务事件；driver 统一查表。缺少 handler 或 transition 时立即抛错，因此新增状态不会因为默认 fall-through 静默跳过。

每个状态都被计时

agent/loop.py:1228事件驱动 driver
while ctx.state is not TurnState.DONE:
    handler = getattr(self, f"_state_{ctx.state.name.lower()}")
    t0 = time.perf_counter()
    event = await handler(ctx)
    ctx.trace.append(StateTraceEntry(
        state=ctx.state, duration_ms=(time.perf_counter() - t0) * 1000,
        event=event,
    ))
    ctx.state = self._TRANSITIONS[(ctx.state, event)]

turn_id = session_key + time_ns 将日志与一次 Turn 关联；trace 同时记录状态、耗时、事件和异常标记，能区分“LLM 慢”与“Session/Context 阶段慢”。

system 消息是特殊路径：_process_message() 会把 channel == "system" 的子 Agent 通知交给 _process_system_message()，因为它需要映射回原始渠道/Session，而不是按普通用户消息完整走一遍状态机。

自测

  • 为什么 priority command 要在创建普通 dispatch task 前处理？
    查看答案收起答案

    priority 命令必须能中断已经占锁的 Turn。若先创建普通 dispatch task 或等待 session lock，/stop 会排在被取消任务之后，失去即时控制意义。

  • COMMAND 的 shortcut 为什么直接到 DONE，而不是 RESPOND？
    查看答案收起答案

    命令 Handler 已经返回或发布了面向用户的 OutboundMessage，再进 RESPOND 会重复组装/发送；COMMAND 因而把结果放到既定返回路径并直接结束状态机。

  • TurnContext 中哪些字段跨越了 BUILD、RUN 和 SAVE 三个状态？
    查看答案收起答案

    session、history、当前 user message、all_messages、user_persisted_early 以及后续的 Runner result/save boundary 共同贯穿这些阶段；它们都集中在 TurnContext。
