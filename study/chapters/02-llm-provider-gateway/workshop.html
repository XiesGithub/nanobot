1. load_config

配置边界先做结构验证，再返回业务代码可读的对象。这里没有发出任何模型请求。

当前源码原文 · nanobot/config/loader.py · load_config · 第 32–56 行（连续摘录）

def load_config(config_path: Path | None = None) -> Config:
    """
    Load configuration from file or create default.

    Args:
        config_path: Optional path to config file. Uses default if not provided.

    Returns:
        Loaded configuration object.
    """
    path = config_path or get_config_path()

    config = Config()
    if path.exists():
        try:
            with open(path, encoding="utf-8") as f:
                data = json.load(f)
            data = _migrate_config(data)
            config = Config.model_validate(data)
        except (json.JSONDecodeError, ValueError, pydantic.ValidationError) as e:
            logger.warning("Failed to load config from {}: {}", path, e)
            logger.warning("Using default configuration.")

    _apply_ssrf_whitelist(config)
    return config
  1. 先创建默认 Config。文件存在时读取 JSON、迁移旧格式、model_validate；不存在时直接使用默认。
  2. JSONDecodeError、ValueError、Pydantic 验证异常会记录警告并保留默认配置；不是所有文件 IO 错误都被这个 except 捕获。
  3. _apply_ssrf_whitelist 是装配副作用。环境引用解析不在这个函数体中，快照加载器随后显式 resolve_config_env_vars，缺失引用可能因此让整个快照失败。

2. Config._match_provider

选择 Provider 不是简单地从模型名截取第一个单词。完整优先级决定了同一模型字符串在不同配置下会使用哪个后端。

当前源码原文 · nanobot/config/schema.py · Config._match_provider · 第 263–326 行（连续摘录）

    def _match_provider(
        self, model: str | None = None
    ) -> tuple["ProviderConfig | None", str | None]:
        """Match provider config and its registry name. Returns (config, spec_name)."""
        from nanobot.providers.registry import PROVIDERS, find_by_name

        forced = self.agents.defaults.provider
        if forced != "auto":
            spec = find_by_name(forced)
            if spec:
                p = getattr(self.providers, spec.name, None)
                return (p, spec.name) if p else (None, None)
            return None, None

        model_lower = (model or self.agents.defaults.model).lower()
        model_normalized = model_lower.replace("-", "_")
        model_prefix = model_lower.split("/", 1)[0] if "/" in model_lower else ""
        normalized_prefix = model_prefix.replace("-", "_")

        def _kw_matches(kw: str) -> bool:
            kw = kw.lower()
            return kw in model_lower or kw.replace("-", "_") in model_normalized

        # Explicit provider prefix wins — prevents `github-copilot/...codex` matching openai_codex.
        for spec in PROVIDERS:
            p = getattr(self.providers, spec.name, None)
            if p and model_prefix and normalized_prefix == spec.name:
                if spec.is_oauth or spec.is_local or spec.is_direct or p.api_key:
                    return p, spec.name

        # Match by keyword (order follows PROVIDERS registry)
        for spec in PROVIDERS:
            p = getattr(self.providers, spec.name, None)
            if p and any(_kw_matches(kw) for kw in spec.keywords):
                if spec.is_oauth or spec.is_local or spec.is_direct or p.api_key:
                    return p, spec.name

        # Fallback: configured local providers can route models without
        # provider-specific keywords (for example plain "llama3.2" on Ollama).
        # Prefer providers whose detect_by_base_keyword matches the configured api_base
        # (e.g. Ollama's "11434" in "http://localhost:11434") over plain registry order.
        local_fallback: tuple[ProviderConfig, str] | None = None
        for spec in PROVIDERS:
            if not spec.is_local:
                continue
            p = getattr(self.providers, spec.name, None)
            if not (p and p.api_base):
                continue
            if spec.detect_by_base_keyword and spec.detect_by_base_keyword in p.api_base:
                return p, spec.name
            if local_fallback is None:
                local_fallback = (p, spec.name)
        if local_fallback:
            return local_fallback

        # Fallback: gateways first, then others (follows registry order)
        # OAuth providers are NOT valid fallbacks — they require explicit model selection
        for spec in PROVIDERS:
            if spec.is_oauth:
                continue
            p = getattr(self.providers, spec.name, None)
            if p and p.api_key:
                return p, spec.name
        return None, None
  1. forced!=auto 时直接 find_by_name，并读取对应 ProviderConfig；无效名称返回 (None,None)，不会偷偷退回自动匹配。
  2. auto 把模型小写并把连字符规范为下划线。带 / 的显式 provider 前缀先于关键词，这避免模型尾部关键词抢占路由。
  3. 前缀与关键词分支都检查该配置存在，且 OAuth/local/direct 或具有 api_key；关键词分支按 PROVIDERS 顺序取第一个。
  4. 没有匹配时先找配置了 api_base 的本地后端，detect_by_base_keyword 更优先；再选非 OAuth 的带 key 后备。没有候选返回空对，由工厂后续检查。

3. make_provider：后端与前置条件

registry 声明元信息，工厂负责构造具体对象；让 AgentLoop 不必知道各 SDK 的构造参数。此摘录覆盖检查与前三类分支。

当前源码原文 · nanobot/providers/factory.py · make_provider：后端与前置条件 · 第 21–62 行（连续摘录）

def make_provider(config: Config) -> LLMProvider:
    """Create the LLM provider implied by config."""
    model = config.agents.defaults.model
    provider_name = config.get_provider_name(model)
    p = config.get_provider(model)
    spec = find_by_name(provider_name) if provider_name else None
    backend = spec.backend if spec else "openai_compat"

    if backend == "azure_openai":
        if not p or not p.api_key or not p.api_base:
            raise ValueError("Azure OpenAI requires api_key and api_base in config.")
    elif backend == "openai_compat" and not model.startswith("bedrock/"):
        needs_key = not (p and p.api_key)
        exempt = spec and (spec.is_oauth or spec.is_local or spec.is_direct)
        if needs_key and not exempt:
            raise ValueError(f"No API key configured for provider '{provider_name}'.")

    if backend == "openai_codex":
        from nanobot.providers.openai_codex_provider import OpenAICodexProvider

        provider = OpenAICodexProvider(default_model=model)
    elif backend == "azure_openai":
        from nanobot.providers.azure_openai_provider import AzureOpenAIProvider

        provider = AzureOpenAIProvider(
            api_key=p.api_key,
            api_base=p.api_base,
            default_model=model,
        )
    elif backend == "github_copilot":
        from nanobot.providers.github_copilot_provider import GitHubCopilotProvider

        provider = GitHubCopilotProvider(default_model=model)
    elif backend == "anthropic":
        from nanobot.providers.anthropic_provider import AnthropicProvider

        provider = AnthropicProvider(
            api_key=p.api_key if p else None,
            api_base=config.get_api_base(model),
            default_model=model,
            extra_headers=p.extra_headers if p else None,
        )
  1. 同一个 model 用于查询 provider_name、配置 p 和 registry spec；缺 spec 时 backend 默认 openai_compat。
  2. Azure 要求 key 与 base；普通 compatible 需要 key，特定 OAuth/local/direct 与 bedrock 前缀有豁免。条件失败用 ValueError 解释配置问题。
  3. 不同 backend 延迟导入各自类，因此选定一种后端不必提前初始化所有厂商客户端。后续分支处理 Bedrock 和通用 OpenAICompatProvider。

4. provider_signature / build_provider_snapshot

快照把 Provider 实例、模型与预算绑成一个切换单元，签名用于判断配置是否真的改变。

def provider_signature(config: Config) -> tuple[object, ...]:
    """Return the config fields that affect the primary LLM provider."""
    model = config.agents.defaults.model
    defaults = config.agents.defaults
    p = config.get_provider(model)
    return (
        model,
        defaults.provider,
        config.get_provider_name(model),
        config.get_api_key(model),
        config.get_api_base(model),
        p.extra_headers if p else None,
        p.extra_body if p else None,
        getattr(p, "region", None) if p else None,
        getattr(p, "profile", None) if p else None,
        defaults.max_tokens,
        defaults.temperature,
        defaults.reasoning_effort,
        defaults.context_window_tokens,
    )


def build_provider_snapshot(config: Config) -> ProviderSnapshot:
    return ProviderSnapshot(
        provider=make_provider(config),
        model=config.agents.defaults.model,
        context_window_tokens=config.agents.defaults.context_window_tokens,
        signature=provider_signature(config),
    )


def load_provider_snapshot(config_path: Path | None = None) -> ProviderSnapshot:
    from nanobot.config.loader import load_config, resolve_config_env_vars

    return build_provider_snapshot(resolve_config_env_vars(load_config(config_path)))
  1. signature 不只包含 model；还包含 provider 选择、key、base、headers、extra_body、region/profile 与生成/窗口参数。修改 temperature 同样是运行配置变更。
  2. build_provider_snapshot 先 make_provider，再提取模型和窗口。其上方的工厂尾部把 defaults.temperature/max_tokens/reasoning_effort 放入 GenerationSettings。
  3. load_provider_snapshot 显式完成 load→环境解析→构造。构造失败则不会拿到半成品快照；不要输出 signature，因为它确实包含敏感配置值。

当前源码原文 · nanobot/providers/base.py · LLMResponse / GenerationSettings · 第 48–86 行（连续摘录）

@dataclass
class LLMResponse:
    """Response from an LLM provider."""
    content: str | None
    tool_calls: list[ToolCallRequest] = field(default_factory=list)
    finish_reason: str = "stop"
    usage: dict[str, int] = field(default_factory=dict)
    retry_after: float | None = None  # Provider supplied retry wait in seconds.
    reasoning_content: str | None = None  # Kimi, DeepSeek-R1, MiMo etc.
    thinking_blocks: list[dict] | None = None  # Anthropic extended thinking
    # Structured error metadata used by retry policy when finish_reason == "error".
    error_status_code: int | None = None
    error_kind: str | None = None  # e.g. "timeout", "connection"
    error_type: str | None = None  # Provider/type semantic, e.g. insufficient_quota.
    error_code: str | None = None  # Provider/code semantic, e.g. rate_limit_exceeded.
    error_retry_after_s: float | None = None
    error_should_retry: bool | None = None

    @property
    def has_tool_calls(self) -> bool:
        """Check if response contains tool calls."""
        return len(self.tool_calls) > 0

    @property
    def should_execute_tools(self) -> bool:
        """Tools execute only when has_tool_calls AND finish_reason is ``tool_calls`` / ``stop``.
        Blocks gateway-injected calls under ``refusal`` / ``content_filter`` / ``error`` (#3220)."""
        if not self.has_tool_calls:
            return False
        return self.finish_reason in ("tool_calls", "stop")


@dataclass(frozen=True)
class GenerationSettings:
    """Default generation settings."""

    temperature: float = 0.7
    max_tokens: int = 4096
    reasoning_effort: str | None = None
  1. 每个响应独立分配 tool_calls 与 usage 默认容器。content 可以 None，reasoning_content 和 thinking_blocks 分开保存，不能混成用户回答。
  2. has_tool_calls 只检查列表非空；should_execute_tools 额外门控 finish_reason。refusal/content_filter/error 即使带有调用对象，也返回 False。
  3. 结构化 error_status_code/error_kind/error_code 等服务于重试；错误不是仅靠 content 中是否出现 Error 字样判断。GenerationSettings 是 frozen dataclass，调用方应覆盖请求值而不是任意就地改字段。

当前源码原文 · nanobot/providers/base.py · LLMProvider.chat_with_retry · 第 563–602 行（连续摘录）

    async def chat_with_retry(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]] | None = None,
        model: str | None = None,
        max_tokens: object = _SENTINEL,
        temperature: object = _SENTINEL,
        reasoning_effort: object = _SENTINEL,
        tool_choice: str | dict[str, Any] | None = None,
        retry_mode: str = "standard",
        on_retry_wait: Callable[[str], Awaitable[None]] | None = None,
    ) -> LLMResponse:
        """Call chat() with retry on transient provider failures.

        Parameters default to ``self.generation`` when not explicitly passed,
        so callers no longer need to thread temperature / max_tokens /
        reasoning_effort through every layer. Explicit ``None`` is also
        normalized to the provider's generation defaults so that downstream
        ``_build_kwargs`` never sees ``None`` for ``max_tokens`` / ``temperature``
        (which would crash ``max(1, max_tokens)``).
        """
        if max_tokens is self._SENTINEL or max_tokens is None:
            max_tokens = self.generation.max_tokens
        if temperature is self._SENTINEL or temperature is None:
            temperature = self.generation.temperature
        if reasoning_effort is self._SENTINEL:
            reasoning_effort = self.generation.reasoning_effort

        kw: dict[str, Any] = dict(
            messages=messages, tools=tools, model=model,
            max_tokens=max_tokens, temperature=temperature,
            reasoning_effort=reasoning_effort, tool_choice=tool_choice,
        )
        return await self._run_with_retry(
            self._safe_chat,
            kw,
            messages,
            retry_mode=retry_mode,
            on_retry_wait=on_retry_wait,
        )
  1. max_tokens/temperature 缺省或显式 None 都用 self.generation 默认值；这样 _build_kwargs 的 max(1,max_tokens) 不会收到 None。
  2. reasoning_effort 仅在 _SENTINEL 时回退；显式 None 保留为关闭/不指定语义。不能对三种参数统一写 value or default，否则 0 等合法输入也被吞掉。
  3. 最终 kw 交给 _run_with_retry(_safe_chat,...)；本段并不无条件循环重试所有错误。上层可选择 retry_mode、接收 on_retry_wait。

同一内部参数需要按厂商能力转换成不同的 wire 字段。本摘录展示模型前缀、消息清理、温度和输出预算映射。

当前源码原文 · nanobot/providers/openai_compat_provider.py · OpenAICompatProvider._build_kwargs · 第 470–511 行（连续摘录）

    def _build_kwargs(
        self,
        messages: list[dict[str, Any]],
        tools: list[dict[str, Any]] | None,
        model: str | None,
        max_tokens: int,
        temperature: float,
        reasoning_effort: str | None,
        tool_choice: str | dict[str, Any] | None,
    ) -> dict[str, Any]:
        model_name = model or self.default_model
        spec = self._spec

        if spec and spec.supports_prompt_caching:
            model_name = model or self.default_model
            if any(model_name.lower().startswith(k) for k in ("anthropic/", "claude")):
                messages, tools = self._apply_cache_control(messages, tools)

        if spec and spec.strip_model_prefix:
            model_name = model_name.split("/")[-1]

        kwargs: dict[str, Any] = {
            "model": model_name,
            "messages": self._sanitize_messages(self._sanitize_empty_content(messages)),
        }

        # GPT-5 and reasoning models (o1/o3/o4) reject temperature when
        # reasoning_effort is active.  Only include it when safe.
        if self._supports_temperature(model_name, reasoning_effort):
            kwargs["temperature"] = temperature

        if spec and getattr(spec, "supports_max_completion_tokens", False):
            kwargs["max_completion_tokens"] = max(1, max_tokens)
        else:
            kwargs["max_tokens"] = max(1, max_tokens)

        if spec:
            model_lower = model_name.lower()
            for pattern, overrides in spec.model_overrides:
                if pattern in model_lower:
                    kwargs.update(overrides)
                    break
  1. model 或 default_model 确定实际模型；仅 spec 允许时附加缓存控制或去掉路径前缀。模型字符串仍受项目配置约束，练习统一使用 deepseek-v4-flash。
  2. 两层 sanitize 清理空内容和厂商消息格式。输出 kwargs 的 model/messages 是实际发送结构，不能把内部 _meta 当 SDK 支持字段。
  3. temperature 只在能力判断允许时发送。输出 token 字段由 supports_max_completion_tokens 决定，否则使用 max_tokens，值至少为 1。
  4. model_overrides 按模式取首次命中并更新 kwargs；因此排查实际请求时必须考虑 spec，而不是只查看 defaults。

8. AgentLoop._apply_provider_snapshot / _refresh_provider_snapshot

切换是装配责任。只更新 loop.model 会让后台归档和子代理继续使用旧设置。

当前源码原文 · nanobot/agent/loop.py · AgentLoop._apply_provider_snapshot / _refresh_provider_snapshot · 第 453–481 行（连续摘录）

    def _apply_provider_snapshot(self, snapshot: ProviderSnapshot) -> None:
        """Swap model/provider for future turns without disturbing an active one."""
        provider = snapshot.provider
        model = snapshot.model
        context_window_tokens = snapshot.context_window_tokens
        if self.provider is provider and self.model == model:
            return
        old_model = self.model
        self.provider = provider
        self.model = model
        self.context_window_tokens = context_window_tokens
        self.runner.provider = provider
        self.subagents.set_provider(provider, model)
        self.consolidator.set_provider(provider, model, context_window_tokens)
        self.dream.set_provider(provider, model)
        self._provider_signature = snapshot.signature
        logger.info("Runtime model switched for next turn: {} -> {}", old_model, model)

    def _refresh_provider_snapshot(self) -> None:
        if self._provider_snapshot_loader is None:
            return
        try:
            snapshot = self._provider_snapshot_loader()
        except Exception:
            logger.exception("Failed to refresh provider config")
            return
        if snapshot.signature == self._provider_signature:
            return
        self._apply_provider_snapshot(snapshot)
  1. _refresh 在没有 loader 时直接退出；加载异常捕获后保留旧 Provider。签名一致也不应用新实例。
  2. _apply 将 Provider、模型、context_window_tokens 更新到 Loop，并同步 runner.provider、subagents、consolidator、dream。
  3. 末尾保存 signature 作为下次比较基准。这里没有持久化 Session 的逻辑，也不能把这几行视为任意并发调度下的全局数据库事务；在轮入口刷新是它的使用前提。

用一组具体数据推演全部变化

固定练习条件：provider=deepseek（显式选择），model=deepseek-v4-flash，对应凭据已配置但不显示，temperature=0.2、max_tokens=512。FakeProvider 不联网，顺序返回一次暂时性错误和一次工具请求。

步骤输入推导结果
1 匹配forced=deepseek直接读取 deepseek 配置；不会扫描其他供应商关键词。
2 构造Registry backend=openai_compat获得兼容 Provider；generation=(0.2,512,配置的 reasoning_effort)。
3 调用max_tokens=None；temperature=0；reasoning_effort=Nonemax_tokens→512；temperature 保留 0；reasoning_effort 保留 None。model 保持 deepseek-v4-flash。
4 首次响应finish_reason=error，error_status_code=503交给基类可靠性策略判定；仅在允许重试时等待并再调 FakeProvider，工具执行数仍是 0。
5 第二次响应tool_calls=[{id:c7,name:read_file,arguments:{path:notes.txt}}]，finish_reason=tool_callshas_tool_calls=True；should_execute_tools=True；Runner 才可执行 c7。
6 反例响应同样 c7，但 finish_reason=refusalhas_tool_calls=True，should_execute_tools=False；执行数必须保持 0。
7 配置更新仅 temperature 0.2→0.3签名变化；下一次轮入口替换快照并传播给四个使用者。若环境引用缺失导致 loader 异常，则保留旧配置。

再检查身份边界：HTTP 接口把请求 model 与应用配置名比较；Provider 工厂选择真实后端；_build_kwargs 才决定 wire model 格式。这三层承担不同任务。把 HTTP model 直接用来临时改工厂会绕开配置与快照的一致性。

独立搭建本章最小模块

从零实现一个无网络的 MiniProviderGateway。输入是普通字典配置和统一请求，输出为自定义 Response dataclass。实现 forced/auto 两种选择、生成参数解析、基于结构化错误的有限重试、工具门控、签名变更传播。所有例子只使用 deepseek-v4-flash；使用假凭据存在性布尔值，不读取实际凭据文件。

展开参考方案：结构、算法与错误处理
  1. 把 registry 表定义为 name、keywords、backend、needs_key。selector 是纯函数，显式指定无匹配应抛清晰错误；auto 先前缀再关键词。
  2. 定义独立 MISSING 对象；max_tokens/temperature 为 MISSING 或 None 时用 generation，reasoning_effort 仅 MISSING 时回退。
  3. adapter 接受 FakeTransport，记录请求字典但排除凭据；Response 保存 finish_reason/error_status_code/tool_calls。执行工具必须同时检查非空调用和成功终止原因。
  4. 用最多 3 次尝试模拟 503→503→成功；401 立即返回错误。sleep 接口注入一个记录器，使验收不真实等待。该规则是练习简化策略，并非生产基类全部策略。
  5. 快照管理先构造新对象再替换指针，构造异常保留旧对象；为 runner、memory 两个假消费者传入同一快照版本。签名内部比较，日志只打印不含秘密的版本号。

验收条件

  1. forced=unknown 必须失败，不能 silently auto。前缀匹配优先于模型尾部关键词。
  2. None 与显式 0 的温度案例按演算得到不同结果；reasoning_effort=None 不恢复默认。
  3. 带 tool_calls 的 error/refusal 不执行工具；连续暂时性错误达到次数上限后停止。
  4. 更新失败保持所有消费者原版本；成功变更后消费者一致。任何输出和日志都没有凭据内容。

边界、不变量与容易写错的地方

  1. ProviderSpec 是声明，Factory 是构造，Provider 是协议适配；HTTP / Session 不应该渗入 Provider 子类。
  2. 配置签名 frozen 不意味着签名里的嵌套 dict 不可变；应把快照作为替换单元，避免外部就地修改 extra_headers。
  3. 不要把所有 429 当可重试。配额耗尽与限速在基类里是不同语义；结构化错误信息比字符串匹配更可靠。
  4. 环境变量缺失、模型参数不兼容和网络暂时失败处于三个不同阶段，修复方向分别是配置、协议映射和可靠性策略。
  5. 本页引用的多厂商分支是源码事实，不是建议改变本仓库运行模型；项目的实际 LLM 调用始终使用 deepseek-v4-flash。
