Gateway 装配与运行时热更新

Gateway 不实现模型协议，但它拥有组装权：确定配置路径、创建一次 ProviderSnapshot，把依赖注入 AgentLoop，并提供后续重新加载函数。AgentLoop 则在 Turn 边界安全传播新的 Provider。

启动装配链

→→→→→

CLI 先加载并解析环境变量

自定义 config path 会先记录，保证启动和后续 snapshot reload 指向同一文件。此时 Gateway 端口、workspace 和 Provider 参数都已类型化。

Provider 配置错误在启动期失败

build_provider_snapshot(config) 内部调用 Factory；ValueError 被 Gateway 转成清晰启动错误，而不是等第一条用户消息到来才失败。

先建立共享基础设施

Gateway 创建 MessageBus、SessionManager 与 workspace CronService；这些对象与 Provider 一起进入 AgentLoop，避免核心类自己读取全局配置。

from_config 负责参数映射

它把 AgentDefaults 与 ToolsConfig 映射成构造参数；Gateway 显式传入已经创建的 provider、model、context window 和共享服务。

Loader 与旧 signature 一并注入

provider_snapshot_loader=load_provider_snapshot 让 Loop 能重新读取；初始 signature 用于快速判断配置是否真的影响 Provider。

Provider 已准备好后才启动事件循环

Cron、Heartbeat、Agent 和 Channels 随后启动。Provider 创建失败不会留下一个接受消息但无法完成 Turn 的半启动 Gateway。

为什么放在 Turn 边界

Provider 是有状态对象，持有 HTTP client、OAuth token 或 circuit breaker。若在一次 AgentRunner 工具循环中途替换，前半段 assistant/tool 历史可能由旧协议产生，后半段却交给新协议，且并发中的 Subagent 也会出现竞态。当前设计只在新消息进入时检查，因此一个已经开始的 Turn 使用稳定 Provider；切换面向未来 Turn。

热更新不是完整 Config 热加载：signature 只覆盖主 Provider 相关字段。providerRetryMode、Gateway host/port、工具与 MCP 配置等不在这条传播链上；修改这些配置通常需要重启。图像生成 Provider 配置也有独立生命周期。
当前实现的资源边界：load_provider_snapshot() 会先构造 Provider，再由 Loop 比较 signature；因此配置未变化时也会短暂创建一个随后丢弃的客户端。真正切换时旧 Provider 也没有统一的 close() 契约。这不改变选择结果，但属于后续可优化的客户端生命周期问题。

Gateway 与 SDK 的差异

Gateway

显式构造 Snapshot 并注入 loader/signature，因此支持逐 Turn 检查；同时装配 Bus、Channels、Sessions、Cron 和 Heartbeat。

Nanobot.from_config()

直接由 AgentLoop.from_config() 创建 Provider，适合进程内调用；当前没有注入 snapshot loader，因此实例不会自动读取文件变化。

自测

  • 为什么 Gateway 要同时注入 snapshot loader 和初始 signature？
    查看答案收起答案

    初始 signature 告诉 AgentLoop 当前已装配的配置版本，loader 提供后续重新读取 snapshot 的能力。两者同时存在，Turn 开始时才能比较而不是无条件重建 Provider。

  • 配置重载失败时为什么继续使用旧 Provider？
    查看答案收起答案

    _refresh_provider_snapshot() 捕获加载/构造异常并保留现有对象。旧 Provider 已可工作，因一次写到一半或无效配置就替换它会让所有新 Turn 立即失效。

  • Provider 切换为什么必须同步 Consolidator 和 Dream？
    查看答案收起答案

    Consolidator 和 Dream 都会直接调用模型，并依赖模型名、context window 和 Provider。只更新主 Runner 会让后台记忆任务继续使用旧端点或错误预算。

  • 为什么 SDK facade 默认没有配置文件热更新？
    查看答案收起答案

    SDK facade 直接用构造时提供的 snapshot 创建 AgentLoop，没有 Gateway 长驻配置文件监听/loader 的装配场景；若调用者需要切换，应显式重建或注入对应能力。
