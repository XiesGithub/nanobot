→→→→

默认路径可被实例覆盖

get_config_path() 默认返回 ~/.nanobot/config.json；CLI 传入自定义路径时用模块级变量保存，后续热加载继续读取同一文件。

缺失文件使用默认模型

load_config() 先构造 Config()。文件存在才读取 JSON；解析或验证失败会记录 warning，并保留默认配置，而不是让 Gateway 使用半解析对象。

兼容旧配置结构

_migrate_config() 在建模前迁移历史字段，例如把旧的 workspace 限制和 MyTool 开关移到新层级。

别名与约束在模型层完成

公共 Base 使用 to_camel 并允许字段名填充，因此 JSON 可写 apiKey，Python 中仍访问 api_key。Field 同时约束范围和兼容别名。

凭证引用单独解析

Gateway/SDK 调用 resolve_config_env_vars()，递归替换字符串中的 ${OPENAI_API_KEY}。变量缺失时抛出明确错误，避免把占位符当作真实 key 发出。

两类“环境变量”不是同一机制

BaseSettings 嵌套变量

根 Config 声明 env_prefix="NANOBOT_" 和 env_nested_delimiter="__"，直接构造 Settings 时支持嵌套环境字段。

配置值中的引用

常规配置文件更常写 "apiKey": "${OPENAI_API_KEY}"；这是 loader 在模型建立后递归解析的显式引用，可用于任意字符串字段和扩展配置。

边界提示：contextWindowTokens 是 nanobot 用于估算与压缩 Prompt 的预算，不会自动从远端模型元数据读取；配置过大可能让请求超窗，配置过小则会更早归档历史。

自测

  • maxTokens 与 contextWindowTokens 分别限制什么？
    查看答案收起答案

    maxTokens 是一次生成最多输出多少 token；contextWindowTokens 是模型可容纳的整次上下文上限，预算计算要同时考虑 system、历史、工具 schema、输入和输出余量。

  • 为什么 apiKey 推荐写成环境变量引用，而不是直接写入 JSON？
    查看答案收起答案

    配置解析支持环境变量引用，启动时再由解析器替换。这样配置文件可以提交或共享而不携带明文凭据，也便于不同环境注入不同 key。

  • JSON 解析失败时 load_config 为什么回到完整默认对象？
    查看答案收起答案

    load_config() 捕获不存在或 JSON/校验失败并返回新的 Config()，保证调用者拿到完整 Pydantic 默认结构；错误配置不会产生半初始化对象。

  • apiBase 为空时，默认地址从哪里补上？
    查看答案收起答案

    Factory 选中 ProviderSpec 后，会使用该 spec 注册的默认 api_base；用户配置的 apiBase 非空时才覆盖它。
