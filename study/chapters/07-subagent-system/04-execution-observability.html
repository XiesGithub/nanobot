Runner 的 checkpoint 更新阶段

没有最终文本也有明确替代

Manager 按 stop_reason 分类

tool_error 回传部分进度，error 回传 Runner error，其余都视为可用结果；外围异常也转换为 announcement，而不是静默丢失。

SubagentStatus 的数据模型

agent/subagent.py:26–39实时而非历史记录
@dataclass(slots=True)
class SubagentStatus:
    task_id: str
    label: str
    task_description: str
    started_at: float
    phase: str = "initializing"
    iteration: int = 0
    tool_events: list = field(default_factory=list)
    usage: dict = field(default_factory=dict)
    stop_reason: str | None = None
    error: str | None = None

状态表用于正在运行时的观察，例如 MyTool 能格式化 Manager 中的 SubagentStatus；task 完成后的 done callback 会把 status 删除，所以它不是审计日志。最终可追溯信息应从父 Session 与日志获取。

工具失败时怎样保留部分进度

agent/subagent.py:277–296面向父 Agent 的错误摘要
completed = [e for e in result.tool_events if e["status"] == "ok"]
failure = next((e for e in reversed(result.tool_events)
                if e["status"] == "error"), None)

for event in completed[-3:]:
    lines.append(f"- {event['name']}: {event['detail']}")
if failure:
    lines.append(f"- {failure['name']}: {failure['detail']}")

错误结果不是只有 “failed”：最多保留最近三个成功步骤和最后一个失败工具，让父 Agent 能解释已完成的工作、决定是否接管或重新委派。

状态语义要按源码理解：Runner 返回后 Manager 先把 phase 设为 done，再依据 stop_reason 选择成功或错误 announcement；tool_error 分支不会把 phase 改回 error，而且状态很快被 cleanup 删除。对外可靠信号是 announcement status/result，不应只盯 phase。

  • Subagent 为什么选择 fail_on_tool_error=True？
    查看答案收起答案

    子任务通常是单一后台工作，若工具失败后继续，最终 announcement 容易掩盖不完整结果。spec 设置 fail_on_tool_error=True，让失败明确进入 FAILED 状态并报告。

  • checkpoint callback 与父 Agent checkpoint 有什么本质差别？
    查看答案收起答案

    子 Agent checkpoint 只保存到 SubagentStatus 供运行期观察，不写父 Session 的 runtime checkpoint；父 checkpoint 用于用户 /stop 后恢复主 Turn 的工具协议。

  • SubagentStatus 为什么不能充当完成历史？
    查看答案收起答案

    Status 是内存中的活动任务快照，done callback 会清理运行表，进程重启也会消失。完成历史依赖 announcement 被注入并由 AgentLoop 保存到 Session。
