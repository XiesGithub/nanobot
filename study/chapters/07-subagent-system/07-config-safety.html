配置如何流到子执行器

→→→→

Schema 声明统一默认值

max_tool_iterations=200、max_concurrent_subagents=1、max_tool_result_chars=16000；ToolsConfig 还控制 exec/web 和 workspace 限制。

AgentLoop 从用户配置取多数值

max iterations、result chars、disabled skills、tools config、workspace policy 与模型信息都传给 Manager。

Manager 保存未来 spawn 的运行参数

Provider 热切换会调用 set_provider；MyTool 修改主 max_iterations 时也会同步到 subagents.max_iterations。

SpawnTool 先执行全局并发检查

当前 running 数达到 limit 就拒绝。该上限跨 session 共享，避免多个用户各自耗尽 Provider 配额。

Runner 与具体 Tool 各守一层

迭代/结果长度由 AgentRunSpec 控制；路径、Shell、环境变量、网络和 SSRF 由对应 Tool 配置与安全模块控制。

失败处理矩阵

可预期失败

并发已满返回 Tool error 文本；tool_error 汇总部分进度；max_iterations 返回替代结果；父等待 300 秒超时后允许当前 Turn 结束。

异常与取消

普通 Exception 被 Manager 捕获并回注 “Error: ...”；CancelledError 传播并走 done cleanup；晚到结果仍可触发独立 system Turn。

源码审阅发现：并发配置没有完整接线

config/schema.py:88–90 + agent/subagent.py:83–98声明存在，传递缺失
# AgentDefaults
max_tool_iterations: int = 200
max_concurrent_subagents: int = Field(default=1, ge=1)
max_tool_result_chars: int = 16_000

# SubagentManager.__init__
defaults = AgentDefaults()
self.max_concurrent_subagents = defaults.max_concurrent_subagents

AgentLoop.from_config() 会把 configured max_tool_iterations 传入 AgentLoop，再传给 Manager；但 AgentLoop 构造函数与 SubagentManager 构造函数都没有 max_concurrent_subagents 参数。Manager 重新创建 AgentDefaults()，因此当前路径只得到默认值 1。测试也只断言它等于新建 defaults，没有覆盖非默认配置。

结论：配置文件中把 maxConcurrentSubagents 改成非 1 值，在当前源码中可能不会影响实际 SpawnTool 上限。这是本章记录的实现缺口，不是手册对代码做出的修复。

其他实现限制

  • Subagent 没有父对话历史；任务描述遗漏背景时无法自动补齐。
  • workspace 共享但没有文件级事务或自动冲突合并，多任务写同一文件需由主 Agent协调。
  • 完成后的 SubagentStatus 被立即删除，没有内置已完成任务列表。
  • Manager 没有独立的全局 shutdown/close API；明确的细粒度取消入口是 cancel_by_session。
  • 没有专门的模型选择、预算分账或每个 task timeout；等待父注入的 300 秒不是子任务执行超时。
  • Subagent 不能 ask_user；遇到缺失信息只能返回问题或失败，由父 Agent重新与用户交互。

扩展 Subagent 时的检查清单

  1. 新 Tool 是否真的需要 subagent scope？它能否在没有 bus、cron、provider loader 的 ToolContext 下创建？
  2. 任务结果是否始终携带 effective session key、task id 和必要的原始消息关联？
  3. 新增并发是否会造成共享 workspace 写冲突、Provider 限流或共享 Runner 状态问题？
  4. 错误、取消、等待超时和父 Turn 已结束四种路径是否都有测试？
  5. 不要把“独立 Registry”误认为进程沙箱；副作用边界必须由 Tool 自己守住。

  • 300 秒等待为什么不是 Subagent timeout？
    查看答案收起答案

    这是 AgentLoop 等待 pending/announcement 的一次超时窗口，超时后只是让当前父 Runner 继续或结束；Subagent task 仍在 Manager 中运行，完成后可走晚到结果的新 system Turn。

  • 独立 ToolRegistry 为什么不能等同于进程级隔离？
    查看答案收起答案

    Registry 隔离只限制模型可见和可调用的工具集合；所有任务仍在同一 Python 进程并共享 workspace、Provider 和操作系统权限，恶意或有副作用的 Tool 仍可影响彼此。

  • max_concurrent_subagents 的配置断点出现在哪两层之间？
    查看答案收起答案

    字段定义在 AgentDefaults.max_concurrent_subagents，但 AgentLoop.from_config() 没把该值传进运行期 Manager；SubagentManager 因而从自己的默认 AgentDefaults() 读取，形成 schema 到装配层的断点。
