Subagent · result delivery

结果不是直接发给用户，而是重新成为父 Agent 的输入

SubagentManager 将 task 与 result 包进一段“请自然总结”的内部消息，再发布到 inbound bus。父 Agent因此能结合原始用户目标、当前 Session 和渠道语气决定最终答复，而不是机械转发子结果。

模板区分成功和失败

status_text 是 completed successfully 或 failed，但两者都回到父 Agent；失败同样需要用户可见的解释或后续行动。

这是内部消息，不是假装用户发言

InboundMessage 使用 channel="system" 与 sender_id="subagent"，AgentLoop 可据此选择专用处理路径。

session_key_override 指向父会话

优先使用 spawn 时保存的 effective session key，兼容 unified session 和 Slack thread；缺失时才回退到 channel:chat_id。

仍通过同一个 MessageBus

Manager 不直接调用父 Runner，也不直接写 Session。总线让结果与普通 follow-up 使用同一并发和路由机制。

是否仍有 pending queue 决定后半程

父 Turn 仍活跃时进入 injection；父 Turn 已结束或等待超时后，则像新消息一样创建独立 system Turn。

这条路径仍会调用主模型，因此用户收到的是结合会话后的总结。它还会执行 Session 保存、Context 治理和后台 consolidation，行为上相当于一次内部触发的新 Turn。

  • Subagent 为什么不直接发布 OutboundMessage？
    查看答案收起答案

    Subagent 不拥有稳定的 channel/chat 投递语义，也不能决定父模型是否要综合结果。它发布带父 origin 的内部 announcement，让 AgentLoop 选择注入、续跑、保存和最终用户回复。

  • 哪一个条件决定结果走同 Turn 注入还是新 system Turn？
    查看答案收起答案

    父 Session 当前仍有活动 Runner 且 injection callback/pending drain 能在等待窗口内接收时走同 Turn；活动 Turn 已结束或无法注入时，announcement 作为带 override 的 system InboundMessage 开启新 Turn。

  • session_key_override 对 unified session 有什么意义？
    查看答案收起答案

    它强制 system announcement 继续使用原父 Session 的历史，即使消息的 channel/chat 为内部 subagent 路由；统一会话模式下不会意外落到新的 system:... 会话。
