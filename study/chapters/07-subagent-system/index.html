Subagent：在一个主 Agent Turn 中委派独立任务

nanobot 的 Subagent 不是另一套服务，也不是拥有长期会话的机器人。它是主模型通过 spawn Tool 创建的后台 AgentRunner：拿到聚焦任务、受限工具和独立消息列表，完成后再把结果注入父会话。

核心心智模型：主 Agent 决定“是否委派以及委派什么”；SpawnTool 保存父请求的路由身份；SubagentManager 管理后台 task 和隔离运行环境；Subagent 自己完成模型—工具循环；结果通过 MessageBus 回到父 Agent，由父 Agent 结合原对话自然回复用户。

一条委派任务的完整链路

→→→→

模型显式调用 spawn(task, label)

这仍是一条普通 Tool call。主模型负责把可独立执行的工作描述成聚焦任务，SpawnTool 不自动拆解原请求。

先登记，再异步执行

Manager 生成 8 位 task_id、SubagentStatus 和 session→task 关系，用 asyncio.create_task 启动执行，并立即向主模型返回 started 文本。

每次运行重新构建能力

Subagent 使用专用 System Prompt、只有 system+task 的初始消息，以及 scope=subagent 的新 ToolRegistry；它不继承父会话历史。

结果伪装成内部入站事件

完成或失败结果被套入 announcement 模板，形成 channel="system"、sender_id="subagent" 的 InboundMessage，并带父 session key。

父 Agent 才面向用户表达

结果若及时到达，进入当前 Turn 的 pending queue；若父 Turn 已结束，则触发新的 system Turn。两条路径最终都让主模型总结，而不是让 Subagent 直接发渠道消息。

共享什么，隔离什么

维度共享隔离/缺失
模型同一个 Provider 与当前 model独立 AgentRunner 调用过程和局部 messages
文件同一个 workspace，副作用彼此可见每次 spawn 新建 FileStates 与工具实例
上下文时间、workspace、可用 Skills 摘要不复制父 Session、Memory、当前对话或父 System Prompt
能力文件、搜索、Shell、Web 等 scope=subagent 工具没有 message、spawn、cron、ask_user、MyTool、MCP 等
路由MessageBus 与父 session/channel 身份没有自己的 Channel 或长期 Session
