Subagent · isolation

隔离的不是 workspace，而是认知上下文和能力集合

每次子任务只收到聚焦 System Prompt 和 task，不复制父对话；同时创建新 ToolRegistry 与 FileStates。但所有子任务仍在同一进程、同一 workspace 上工作，因此文件副作用是共享的。

_build_tools() 每次返回新实例

ToolLoader 以 subagent scope 加载工具，并给文件工具注入新的 FileStates()，防止一个子任务的“已读/已改”缓存污染另一个。

System Prompt 只描述子任务身份

包含当前时间、workspace、可用 Skills 摘要和外部内容不可信规则；没有父 Agent 的完整 bootstrap、Memory 和渠道对话历史。

初始消息固定为两条

[system_prompt, {role: user, content: task}]。父 Agent 必须在 task 中写清背景、目标和期望输出，否则子 Agent 无从推断。

执行循环与主 Agent 同源

AgentRunner 仍会向 Provider 发送 Tool definitions、执行多轮工具调用并治理工具结果；隔离来自 Spec，而不是另一份 Runner 代码。

文件系统并未复制

workspace 路径与主 Agent相同。子 Agent 写入文件后主 Agent立即可见；多个子任务若写同一文件仍可能发生业务级冲突。

工具 Registry 的构建

agent/subagent.py:103–120只加载 subagent scope
def _subagent_tools_config(self):
    return ToolsConfig(
        exec=self.tools_config.exec,
        web=self.tools_config.web,
        restrict_to_workspace=self.restrict_to_workspace,
    )

def _build_tools(self):
    registry = ToolRegistry()
    ctx = ToolContext(
        config=self._subagent_tools_config(),
        workspace=str(self.workspace),
        file_state_store=FileStates(),
    )
    ToolLoader().load(ctx, registry, scope="subagent")
    return registry

声明 subagent scope 的第三方 Tool可被 ToolLoader 发现MyTool、主 Registry 的 MCP wrappers

这里的白名单由各 Tool 类的 _scopes 决定，而不是 Manager 硬编码名称。插件也可声明 subagent scope，但它创建时只能依赖当前 ToolContext 已提供的 workspace、config 和 FileStates。

专用 Prompt

templates/agent/subagent_system.md聚焦而非继承
# Subagent

{{ time_ctx }}

You are a subagent spawned by the main agent to complete a specific task.
Stay focused on the assigned task. Your final response will be reported back to the main agent.

## Workspace
{{ workspace }}

## Skills
Read SKILL.md with read_file to use a skill.

SkillsLoader 只生成摘要，真正使用某项 Skill 时需要 read_file 渐进加载；disabled_skills 与主配置保持一致。Prompt 还 include 不可信外部内容规则，提醒 web_search/web_fetch 结果不能作为指令执行。

“隔离”不是安全沙箱：子 Agent 与主进程共享 Python 进程、Provider 凭据和 workspace。安全性依赖文件路径限制、ExecTool 配置、Web SSRF 规则和受限 Tool scope；新 Registry 主要解决状态污染与能力最小化，不能隔离恶意本地代码。

  • 子 Agent 隔离了哪些状态，却共享了哪些副作用？
    查看答案收起答案

    它隔离 messages、Runner 迭代、ToolRegistry、FileState 和请求上下文；但仍共享进程、workspace 文件系统、Provider/外部服务，因此文件与网络副作用并非安全沙箱。

  • 为什么没有 spawn Tool 能防止递归爆炸？
    查看答案收起答案

    子 Registry 采用 subagent scope，不注册 SpawnTool；模型即使生成 spawn 名称也无法解析执行，从能力层阻断递归委派树爆炸。

  • 父 Agent 为什么必须把必要背景写进 task？
    查看答案收起答案

    子 Agent 不读取父对话历史，只收到专用 system prompt 和 task 文本。Manager 无法猜测隐含指代，所以父模型必须在 task 中包含目标、约束、路径和必要上下文。
