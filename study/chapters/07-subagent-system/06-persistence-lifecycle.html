去重规则

agent/loop.py:1544–1566task id 幂等
if not msg.content:
    return False
task_id = msg.metadata.get("subagent_task_id")
if task_id and any(
    m.get("injected_event") == "subagent_result"
    and m.get("subagent_task_id") == task_id
    for m in session.messages
):
    return False
session.add_message(
    "assistant", msg.content,
    sender_id=msg.sender_id,
    injected_event="subagent_result",
    subagent_task_id=task_id,
)

去重只对带 task_id 且已经以 subagent_result 标记持久化的消息生效；空内容直接跳过。结果作为 assistant 事实保存，而不是伪装成新的用户请求。

asyncio.CancelledError 不属于 _run_subagent 的普通 Exception 处理，因此被取消的子任务通常不会发布“失败”announcement；取消信号向外传播，done callback 仍负责移除活动记录。

  • 为什么 announcement 必须在 done callback 清理前发布？
    查看答案收起答案

    done callback 最终会从活动表删除 task/status；announcement 构造需要读取父 origin、结果和状态。因此执行协程先发布完成消息，回调再清理，避免结果失去路由信息。

  • 晚到结果为什么先写 Session 再调用主模型？
    查看答案收起答案

    先持久化 Subagent 完成事实，保证随后主模型调用失败或进程退出时结果仍可恢复；然后再让主模型读取该 system Turn，决定如何总结给用户。

  • 被 /stop 取消的 Subagent 为什么通常没有失败 announcement？
    查看答案收起答案

    /stop 调用 cancel_by_session() 主动取消子 task；取消是用户期望的控制流，协程重新抛出 CancelledError，通常不把它包装成 FAILED announcement 来打扰用户。
