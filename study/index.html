从阅读到独立实现的五个里程碑

顺序与阅读入口你要交付什么过关信号
① 消息全链路 → Provider 契约画出一条用户消息跨过哪些边界；写出统一模型响应结构能区分 request ID、session key、tool call ID；更换 Provider 不改变 Runner
② Runner → 工具 → 运行最小项目实现模型→工具→观察→最终答复的受限循环合法调用完成往返，非法参数不执行工具，迭代用尽可观察地停止
③ 会话与记忆 → 上下文持久化事实、构建有预算的模型输入副本两会话不串数据；重启可续聊；裁剪后工具消息仍成对
④ 子代理 → 自动化 → 命令给后台任务设计归属、结果回注、取消与确定性控制接口结果回到正确父会话；调度状态可解释；命令不需要模型猜测
⑤ 综合实作与扩展验收为自己的需求写模块接口、状态图和失败测试，修改教学项目可以独立说明每个状态由谁拥有、何时持久化，以及失败后是否允许重试

一条消息如何成为一次行动

按箭头推演：同一条消息先确定会话，再构建模型输入。模型提出的工具调用只有经过运行时校验才执行；结果带原调用 ID 回填，形成反馈循环。持久化由应用侧负责，Provider 负责协议转换。失败路径必须受次数、时间或取消约束，不能无限重试。

先把这些边界分清

术语准确含义不要混淆
Turn / iteration一次用户请求的处理 / 其中一次模型调用与可能的工具执行一个 Turn 可以经历多次 iteration
Session / Context可持久化会话事实 / 当前一次模型请求的输入视图为了预算裁剪 Context 不等于删除事实
Memory / history抽取和整理后的长期知识 / 发生过的对话事件摘要、知识和原始事件有不同恢复能力
Tool / Skill / MCP可调用能力 / 提示性操作知识 / 连接外部能力的协议有 schema 或提示不代表实现了执行授权与隔离
并发 / 隔离 / 幂等允许同时推进 / 状态互不污染 / 重复执行不会重复产生副作用asyncio task 不是进程沙箱；恢复 checkpoint 不自动保证 exactly-once
