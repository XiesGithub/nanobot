# 学习手册审计与教学改进

审计基于 2026-09-05 当前工作区的 `study/` 和项目实现。改进前基线：65 页、98 个 pre 代码块、0 幅 SVG、412 个跳出 study 的本地链接（80 个不同目标）、61 组自测、211 道已有答案。

## 具体缺点与改进依据

| 缺点 | 现有证据 | 对学习的影响 | 改进 |
|---|---|---|---|
| 代码块有数量，但真实控制分支不足 | Runner 页主骨架使用 govern、tool_result_messages 等教学简写，省略 checkpoint/错误细节 | 容易把示意函数误当成可复制实现，不能从条件推演状态 | 9 章新增带文件、符号和行区间的连续原文摘录；先说明上下文，再逐段推演，不把摘录当独立程序 |
| 数据图以线性步骤和分层卡片为主 | 没有 SVG；现有 flow 卡片多表示调用步骤 | 读者难以分清输入/输出对象、反馈循环、分支、写入时机 | 每模块新增离线 SVG，标出数据、回流与失败分支，并配文字等价说明 |
| 学习路径依赖同级仓库 | 412 个本地链接跳到 nanobot、tests 或 README | 单独复制 study 后断链；读者还需要自行从大文件里寻找关键逻辑 | 将阅读入口改为手册内部的摘录或模块精讲，保留来源标记；自动阻止新的跨目录链接 |
| 自测重解释、轻实现 | 211 道问答主要检验“为什么”“是什么” | 能复述不等于能决定接口、控制状态或处理失败 | 增加每章设计任务、参考方案、故障用例与可观察验收 |
| 缺少从需求到模块的综合训练 | 9 章围绕已有实现分组，没有统一独立成品 | 容易照抄类名，不能在新场景中决定边界 | 第10章提供可搬走的标准库多模块Agent、完整代码和测试，按里程碑扩展至生产能力 |
| 校验无法证明独立阅读 | 原检查仅检查目标是否存在，不核对 fragment、目录覆盖和摘录漂移 | “检查通过”仍可能跳错位置、需要仓库或引用过期源码 | 增加内部锚点、离线资源、catalog覆盖；可选逐字核对摘录来源 |

## 面向实现的学习目标

读者应能提交而非仅描述以下成果：

1. 给“一个消息完成一次工具调用并生成回复”的需求画出模块依赖和数据流；区分 Channel、应用编排、Runner、Provider、Tools、Session。
2. 写出统一请求/响应和 ToolCall 契约，并举出未知工具、非法参数、空输出和预算耗尽各自的处理方式。
3. 演算一条含工具调用的消息轨迹，验证调用 ID 配对、Session 隔离和模型请求视图不破坏持久化事实。
4. 独立运行并修改第10章教学项目；在新目录中增加工具并用失败用例验证边界。
5. 从业务约束选择是否引入总线、并发、中断、长期记忆和后台调度；解释实现成本、状态所有权与重试/幂等策略。

## 内容层级与诚实标注

- 原专题页用于快速建立概念和关联，不删除已有折叠问答。
- 新增精讲页的“源码原文”是当前版本的连续片段，含来源元数据，可由检查器核验。
- 原骨架统一提示为讲解用简化示意，实际语义以邻接原文精讲为准。
- 第10章是可运行的教学实现，不声称逐功能复制 nanobot；真实 Provider、外部执行工具、MCP、长期记忆、后台调度等的缺口明确列出，并设计后续验收任务。
- 源码地图优先定位同文件的代表性摘录；未逐行收录的源文件指向所属模块设计页，并显示“模块讲解”，不会冒充逐行源码浏览器。

完成这些材料只提供能力训练和自评依据，不能保证任何读者仅浏览页面就掌握所有生产级实现。
